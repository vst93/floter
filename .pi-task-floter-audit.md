# Floter — Prioritized Optimization & Iteration Directions

A focused audit of the Floter codebase. The user wants bite-sized iterations that move the app from "working prototype" to "polished, native-feeling Tauri 2 app." Each item is concrete: a file, the line range, and a specific change.

## Tier 1 — Quick wins, high visible impact (do these first)

### 1.1 Stub the `terminalbar` drag handle (no native drag at all today)
**File:** `src/styles/terminal.css:39-101`
The terminal header is `height: 5px` and only expands to 28px on hover. The whole bar is the drag handle, but it's the only drag target on the panel. Native launchers (Raycast, Spotlight) keep the bar always visible at ~28-32px so the user always sees the affordance and can grab it without hunting.
- Change `.terminal-bar` base `height` from `5px` to `28px` and stop toggling it on hover.
- The `pointer-events: none` on `__identity` and `__actions` already keeps it a clean drag surface — just remove the `transition: height` and the `:hover` size rule.

### 1.2 Settings sidebar isn't a listbox — Up/Down on the focused page doesn't work
**File:** `src/App.tsx:1584-1592` (sidebar `onKeyDown`), `src/styles/settings.css` (look for `.settings-sidebar__item:focus-visible`)
The sidebar listens for `ArrowUp`/`ArrowDown` only when a sidebar button has focus. From the body, `Tab` works but `↑/↓` (the native settings-panel convention) does nothing. Add a window-level keydown for `mode === "settings"` that mirrors the existing logic in `useAppKeyboard.ts:208-222`, and remove the duplicated per-button handler.

### 1.3 Quit confirmation is just a `window.confirm` (line 268 of `useLauncherActions.ts`)
`runSystemAction` uses `window.confirm(...)` for restart/shutdown. On a borderless transparent window, this fires a browser dialog that does not match the panel's frame, has no keybind to dismiss it from the keyboard, and on some Linux compositors steals focus and breaks the very `hide-on-blur` flow that dismissed the window. Replace it with an in-app confirmation banner (see how `SessionsPage.tsx:166-196` does the inline kill-confirm), with `Esc` cancel and `Enter` confirm.

### 1.4 Tray menu is not translated, and has no keyboard accelerators
**File:** `src-tauri/src/lib.rs:141-160, 1152-1161`
`tray_labels` is called once on startup — if the user changes language in settings, the menu stays English until restart. Wire `apply_tray_language` to a settings change listener (it already exists; the only caller is the run-once block in `setup`). Also add accelerator hints: Tauri menu items accept a `Cmd+Q`-style string in `MenuItem::with_id(..., accelerator)`. The current items take none.

### 1.5 Save-failed indicator has no visible trigger path
**File:** `src/App.tsx:1619-1637`
The `settingsSaveFailed` banner renders only when `commitSettings` rejects (line 277-291), but every `changeGeneralSetting` call (line 1290-1298) is fire-and-forget — it never invokes the same path that flips the flag. Either route all changes through `commitSettings` (so failures show), or wire the failure into the catch block of `persistSettings` in the inline save path.

## Tier 2 — Visible UX friction

### 2.1 Session-name list in `SessionsPage` is unordered and dense
**File:** `src/SessionsPage.tsx:108-200`
Sessions are listed in the order the broker returns them, which on a fresh daemon is whatever the broker happened to start with. Sort by `createdAt` desc (most recent first) and add a quiet "Sort by" toggle. The empty state at `:102-106` is a single muted line — a panel like this reads better with a small illustration-style icon + action hint.

### 2.2 Action-bar icon `$` looks like an error/reg-ex indicator
**File:** `src/launcher/LauncherResults.tsx:87-112`
The shell-class action bar uses a raw `$` glyph as its icon (line 88). Compare with the system command "Restart" / "Shut Down" rows that use a proper SVG. Replace with Lucide's `Terminal` (already imported in `App.tsx:14`) for consistency.

### 2.3 Power actions are not in the action bar (only in numbered results)
**File:** `src/hooks/useLauncherCatalog.ts:488-498`, `src/launcher.ts:245-269`
Typing "restart" with no result is a valid input — but `classifyActionBar` returns `"shell"` and the action bar always runs through the shell, so Enter on a bare "restart" runs `restart` as a command, which only works if it's on PATH. The system command shortcut the action bar exposes should recognize the three power actions (`restart`, `shutdown`, `clipboard`) and route to the same handlers `runLauncherItem` already uses for typed results.

### 2.4 No "remove from history" path for typed commands
**File:** `src/hooks/useLauncherCatalog.ts:620-624`
`rememberCommand` builds a 20-deep FIFO list, but there's no UI to inspect or prune it. A user typing the same wrong command repeatedly has no way to clean it up. Add a small "history" affordance in the collapsed card footer (e.g. ↓ glyph next to the input), wired to existing `history` state.

### 2.5 `runLauncherItem` silently no-ops on an unavailable command
**File:** `src/hooks/useLauncherActions.ts:316`
Line 316 shows `extensions.runtimeUnavailable` feedback only after the user clicks. When the user navigates to a disabled command row with arrows and presses Enter, they get the same "click feedback" rather than a clearer "this can't run" indicator. Use the existing `warnings` array on the `LauncherItem` (already populated for runtime-unavailable at `useLauncherCatalog.ts:448-450`) to render an inline disabled hint in the row.

### 2.6 The collapsed card has no visible keyboard hint
**File:** `src/App.tsx:1769-1857`
Other surfaces (terminal, settings) show a title-bar with action buttons. The collapsed card has the input, then two 28x28 icon buttons. Power users learn the keyboard discipline quickly, but new users have no visual cue that `↑/↓` navigates, `Tab` accepts a completion, or `Esc` hides. Add a one-line "?" affordance to the input row that shows the keymap on hover, or a single muted ⌘ glyph that opens a 3-line cheatsheet popover.

## Tier 3 — Native-app patterns missing or weak

### 3.1 No first-run / "what is this" experience
**File:** `src/App.tsx:838-840`
On first launch `settingsHydration.finish()` flips the load promise, but the empty launcher state with the placeholder `"Type a command or app name"` is the only onboarding. Add a one-time "Tip" callout the first time the user opens the launcher: dismissible, persisted in settings as `seen_tip: boolean`. Three native launchers do this — it's expected.

### 3.2 No `Recent` affordance for the SHELL action bar
**File:** `src/hooks/useLauncherCatalog.ts:341-373`
The "Recently launched" list is application-only. The history of typed commands (kept at `useLauncherCatalog.ts:204-205, 620-624`) is never exposed in the empty-query state. Show the last 3 typed commands at the top of the empty query, between recents and a divider.

### 3.3 Pinned card has no z-index guarantee over the main view
**File:** `src/styles/pinned-card.css:1-30` (likely)
The card is mounted in every mode (`App.tsx:1505-1524`) but its z-index is whatever it ends up with. If the user pins while a settings panel is up, the card may sit behind the settings card. Set `z-index: 6` on `.pinned-card` so it floats above all surfaces except the modal-like update banner.

### 3.4 No "search providers" callout for empty results
**File:** `src/App.tsx:1862-1915`
When `launcherResults.length === 0 && !actionBar`, the `launcher-bottom-clip` collapses to nothing (`launcher.css:165-178`). That's fine, but a user with the `show_commands_in_search` toggle off who types `git` sees nothing, with no hint that integrations are off. A one-line greyed-out "Type a command, or enable integrations in Settings" footer would be cheap and very helpful.

### 3.5 Tray menu has no "Reload" / "Open settings" entries
**File:** `src-tauri/src/lib.rs:1152-1180`
Only `Show` and `Quit`. Native launchers have at least 4: Show, Settings, Reload, Quit. The "Reload" is useful because the user may want to force a re-scan (the existing `check_applications` is exposed to the frontend; surface a thin `reload_applications` IPC to clear and rescan).

## Tier 4 — Performance bottlenecks

### 4.1 `terminal-broker` reconnect polling is hardcoded 150ms
**File:** `src-tauri/src/terminal/broker.rs:26, 771, 985, 1077, 1231`
`RESIZE_POLL = 150ms` and the daemon/parser/worker threads each `tokio::time::sleep(20-50ms)` in their shutdown loops. A floter that sits idle with no terminal open still spins these threads (the daemon is started by the broker connection; lazy daemon-spawn on first session would help). Replace the shutdown-loop `sleep` with a `Notify`/channel signal so they exit within microseconds of `alive.store(false)`.

### 4.2 `decodeFrame` runs synchronously in the main thread
**File:** `src/terminal/render.ts` (not yet read in full; `useTerminalView.ts:328` calls `decodeFrame(event.payload.frame)`)
`decodeFrame` base64-decodes a full frame on the JS main thread for every frame. For a 200x50 grid that's 13 * 10000 = 130kB of base64 per frame, decoded and copied on every paint. Two options:
- (small) move the decode to a `Worker` and post the resulting `Uint8Array` to the main thread, or
- (smaller) keep decode main-thread but batch: drop any frame whose `id` and `generation` match the previous event but whose `frame` is identical (cache by hash).

### 4.3 Frontend `term_list_sessions` re-fires every 5s for the visible Sessions page
**File:** `src/SessionsPage.tsx:75-80`
Fine, but the interval keeps firing even when the user is on a different page (it doesn't — it's scoped to the page mount). However, `refreshTerminalSessions` (App.tsx:396-416) is also called every time the user navigates to sessions (App.tsx:447, 1582, 1591). That's three refresh triggers stacked in 100ms when the user clicks the sidebar item. The `beginRequest` guard makes only the last one count, but the first two still race a no-op round-trip. Add a 500ms debounce on `setSessionsLoading(true)`.

### 4.4 `useTerminalView` re-binds the wheel listener on every font/theme change
**File:** `src/hooks/useTerminalView.ts:390-424` (the useEffect with `onWheelNative`)
Wheel handler is bound with `{ passive: false }` to the canvas — the binding survives `relayout`, but the `useEffect` dependencies include `fontFamily, fontSize, terminalMounted, mode`. Every font change tears down the listener, the blink interval, the ResizeObserver, and rebuilds the renderer (line 422-423). For an end user dragging a font-size slider in settings while a terminal is up (rare, but legal), this is a re-paint storm. Split the listener-attachment effect from the renderer-rebuild effect so font size only triggers a `measureCell`, not a fresh renderer.

## Tier 5 — Architecture smells

### 5.1 `App.tsx` is 2020 lines and growing
The big "extracted hooks" comments (`useTerminalView`, `useLauncherCatalog`, `useLauncherActions`, `usePinCoordinator`, `useAppKeyboard`, `useTimedFeedback`) are good — finish the job. The remaining hot spots:
- The 100+ line `useEffect` at `App.tsx:899-963` (mode transition) belongs in `useModeTransition.ts`.
- The settings-save machinery (`settingsSaveTimer`, `settingsSaveGeneration`, `commitSettings`, `persistSettings`, `changeOpacity`, `changeFontSize`, `changeGeneralSetting`, `changeLaunchAtStartup`, `changeTheme`, `changeLanguage`) at `App.tsx:267-1340` is a self-contained `useSettings` hook. The 16 useState hooks at `App.tsx:191-265` similarly split into per-domain hooks (`useSettings`, `useTerminalSessions`, `useUpdateFlow`).
- The 100-line `pinnedCardElement` JSX at `App.tsx:1505-1524` plus the whole `if (mode === "settings")` / `if (mode === "plugin")` / `if (mode === "collapsed")` branches at `:1526-1920` should be a `<Surface mode={...} .../>` component that takes only the props it needs.

### 5.2 `eprintln!` debug logging is the only logging
**File:** all of `src-tauri/src/`. ~26 `eprintln!` calls (`lib.rs:224, 498, 1076, 1150, 1245, 1256`; `terminal/broker.rs:1291`; `extensions/install.rs:1558`; `clipboard_history/monitor.rs:88, 128, 133, 383`; etc.)
The first one (`lib.rs:224`) prints every cursor-monitor resolution to stderr every time the panel is summoned. Wire up `tracing` (or `log` + `env_logger`) with a `RUST_LOG` env var, and gate these by level. Otherwise, on macOS Console.app the user sees a flood of `floter: cursor (1234, 567) -> monitor ...` lines.

### 5.3 `cancelShortcut`, `toggleRecording`, `captureShortcut` are inline closures in `App.tsx`
**File:** `src/App.tsx:1342-1497`
~155 lines of imperative shortcut handling with optimistic UI + rollback. This deserves a `useShortcutCapture` hook that returns `{ toggle, cancel, capture, rejectedAction, recordingAction }`. The pattern of "optimistic update + IPC + rollback on error" repeats for `changeLaunchAtStartup` (`:1314-1340`) and `clearClipboardHotkey` (`:1386-1404`) too — extract a `useOptimisticSetting` helper.

### 5.4 `clipboard/main.ts` is 684 lines of imperative DOM manipulation
**File:** `src/plugins/clipboard/main.ts`
This is the iframe-hosted page (the clipboard history). It hand-renders rows with `document.createElement` and re-runs the whole render on every state change. Convert to a tiny component-less pattern: split into pure `renderRow(entry, index, selected)` and `renderEmpty()` functions called from one `render()` orchestrator. Add a `data-id` attribute to rows and only update the changed ones (a hand-rolled DOM diff). For the typical "I copied something, then pressed ↓↓" workflow the entire list re-renders today for a single selection change.

### 5.5 `extensions.css` is 1421 lines — the largest CSS file
**File:** `src/styles/extensions.css`
The integrations page is rich; that's fine. But a quick `grep "var(--" extensions.css | wc -l` will likely show a few dozen custom properties defined inside the file that probably belong in `base.css` next to the other tokens. Move shared design tokens (`--extension-*`, `--drawer-*`) into `base.css` and keep `extensions.css` for layout only.

## Tier 6 — Low-priority polish

### 6.1 Tooltip on the action-bar Enter glyph
**File:** `src/launcher/LauncherResults.tsx:239-263`
The right-side `launcher-action-bar__hint` shows the formatted Enter shortcut. It uses no `title` attribute, but a screen reader user has no a11y label. Add `aria-label={t("launcher.runInShell")}` on the action-bar button.

### 6.2 Empty clipboard page should explain privacy, not just say "Nothing copied yet"
**File:** `src/plugins/clipboard/main.ts:240-247` (and `src/i18n.ts:96-98`)
`clipboard.empty` is a one-liner. The page hint at `i18n.ts:90` (`settings.clipboardPrivacy`) explains the local-only nature — surface it in the empty state with a small "stored locally only" line under the empty message. This converts "why isn't my cloud clipboard here?" into a feature moment.

### 6.3 The `Record launch` is keyed on `app.path` (filesystem string)
**File:** `src/hooks/useLauncherCatalog.ts:627-640`
`recordLaunch` increments `settings.launch_counts[path]`. If the user moves an app or macOS re-signs a bundle and the path changes, the count resets silently. Use the existing `app.id` (the launcher already keys on it for `LauncherItem` at `useLauncherCatalog.ts:364, 421`) and persist the `path → id` mapping.

### 6.4 The session row's "exited" state shows `exited` but not the code in the row
**File:** `src/settings/SessionsPage.tsx:111-117`
`state` is one of "Running · attached/detached" or "Exited" — but the broker already returns `exitCode`. A session that exited with code 137 (OOM-killed) looks identical to one that exited cleanly. Append `· exit N` when `session.exited && session.exitCode !== 0`.

### 6.5 `terminal` text input element has no visible focus ring
**File:** `src/styles/terminal.css:188-190`
`.terminal-panel__mount:focus-within` adds a 1px inset accent edge. The textarea is `opacity: 0` and `pointer-events: none` — focus on it never visually happens. Either drop the rule or make it toggle on the renderer's "ready" state, so users see when their keyboard really is in the terminal vs the side card.
