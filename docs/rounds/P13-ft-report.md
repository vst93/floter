# P13-ft 报告：用户数据再长，也只吃自己那一列

## 0. 这轮做了什么（一句话）

设置页里有一类标签**不是本仓写的**（扩展自报的包名 / 命令名 / 别名），本轮把「窄窗 × 长标签 ×
长值」三者同时拉到极限，量出 `cardRow` 的每一格都已在**自己的列里收口**：135 字符包名多出的
356px 全部落在名字列内，版本、开关、别名框**一格都没动**。**零像素改动**，三条 pin 进仓库。

## 1. 先量（真实代码路径，720 = `launcher.InputWindowWidth`，深浅逐值相同）

| 量 | 短数据（`V Tools` / `One command`） | 长数据（135 / 120 / 40 字符） |

| 标题行 · 版本 x | 287.8 | **653.8**（名字列右沿 + 12u gap） |
| 标题行 · 名字墨 | 237..285 | 237..**641**（列右沿 645.8） |
| 命令行 · 开关盒 | 657.4..689.8（32.4 宽） | **657.4..689.8**（同 x、同宽） |
| 命令行 · 名字墨 | 200..278 | 200..**641**（列右沿 645.4） |
| 命令行 · 召唤行墨 | 200.. | 200..**640** |
| 命令行 · `Alias` 列 x | 200.8 | 200.8 |
| 命令行 · caption 行距 | 17 / 17 | 17 / 17 |

560（生产不可达，见下）同样不越界：命令名墨到 478、开关 497.4..529.8、卡框右沿 543.8。

「窄」这一维为什么不可达（本轮复核，不抄旧结论）：`shell.go:4743-4745` 对 `SurfaceSettings`
一律返回 `launcher.InputWindowWidth`（720）；`shell.go:1316-1320` 只有终端可 resize；
`UIScale` 只改高度（`SettingsHeight`，`shell.go:4796-4804`）。560 那一臂留作**余量证明**，
不是可达路径——一条只在 720 成立的规则是巧合，不是规则。

## 8. preflight 逐条（A / B / C / D2）

- **A 反套路**：零像素、零文案、零渐变/发光/纯黑/斜体（`noitalic_test.go` 仍绿）；没有新增卡片、
  没有三等分横排。产物是三条 pin 与一节合约。
- **B 设计读取一致**：读取为「桌面命令面板的设置页，面向每天用键盘的人，轻便液态玻璃的语言」。
  本轮判据一条——**用户数据不是设计变量**：发布者写多长，行的骨架都不许变。三个量（版本 x、
  开关盒、`Alias` 列）证明它成立。
- **C 动效抽查**：不动效。`renderIn` 已推进 500ms 越过 120ms 的颜色过渡，读到的是稳定帧。
- **D2 中文页**：本轮**不新增一个汉字**（i18n 红线）。既有缺口仍是 `tokens.Caption` 9.9px /
  正文 10.8px 对「正文 ≥ 14px」——**需拍板**，本轮不动。
- **A4.1（Carbon 决策门）「disabled / read-only / hidden 语义没有混淆」**：本轮不碰状态面
  （P13-fi 已收口）。
- **P-1（禁斜体）/ P-5（可读性优先）**：零墨色改动。
