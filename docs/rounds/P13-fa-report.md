# P13-fa 报告：读数行窄窗边界的「先量」——量出为不可达，不加 `SingleLine()`

轮号 P13-fa（HEAD 前 P13-ez）。方向：通用队列 · 边界情况。表面 = 常规页 · 透明度卡
唯一一行读数（`a.effectiveOpacity` 的 `SpaceBetween` 两段）。

## 结论一句话

P13-ez 动过的读数行是 `SpaceBetween` 两段（名字 + 数值），窄窗 + 中文长串会不会
相撞/回绕？**先量后改**：720 / 614 / 420 × en/zh 六臂实测**永不重叠、永不换行、
永不塌**；退化只出现在 <360px，而设置窗不可缩放、恒问 720 契约宽，那个宽度在
可达域之外。**所以不加 `SingleLine()`、不让名字让位**——那会把「能换行的安全退化」
换成「截断」，可达域里根本没有要救的场面。一行生产代码都没动，边界被钉成 pin。

## mutation（3 条实跑）

1. **M1** 名字右沿断言 `>` 改为 `<`（要求可达布局必须重叠——不可能满足）：
   **六臂全红**，报错串 `the name's right edge 284.4 overlaps the value's left edge 654.2 (§6.122 — 可达域内永不重叠)`。
2. **M2** 非塌断言 `value.W <= 0` 收紧为 `value.W <= 80`（真值 36 满足不了）：
   **六臂全红**，报错串 `a segment collapsed to invisible (name 84x17, value 36x17)`。
3. **M3** 重叠断言改写为 `!(value.X >= name.X+name.W)`（等价写法）：
   **全绿**，已知覆盖边界（逻辑等价重排不改变判定）。

每次注入后 `touch` 复跑（避免测试缓存复用）；还原后 `md5sum -c` 逐字节核对
（`3de4899d…`），`touch` 再复跑全绿。出图裁窗坐标在 mutation 之后做过一次修正
（350 帧原先裁出窗口右沿，改为从 x=0 裁窗内全宽），故最终文件 md5 为
`475dcfab…`；修正只动 dump 的裁窗几何，pin 逻辑一字节未变。

**偷了什么**（逐条落成具体数值）：

1. **`craft-loop.md` 二·工艺密度菜单第 6 项「编辑细节」的「先量后改」原则**：落成
   「探针先跑、表格量完、再决定动不动」——本次量出不可达，于是决定**不动**，并把
   测量表写进合约 §6.122 和报告，而不是凭感觉加 `SingleLine()`。
2. **`chinese-typography.md` 的字宽事实**：中文串（`有效不透明度` = 6 字 × 10.8 ≈
   66px）比英文串（84px）窄 18px，所以 zh 在 350px 仍单行而 en 已换行——「中文长串
   会撞」的担心被字宽数据驳回，落成「zh 臂在 614/420 必须仍不撞」的断言。
3. **`craft-loop.md` 三·两轮制**：第一轮 = 探针量表（6 臂 × 8 宽度）；第二轮 = 只把
   结论钉成 pin 并修正出图裁窗，不顺手改任何别的。
