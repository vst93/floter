# P13-fy 规格：边界情况第二格 —— 「恰好一件」与「一件都没有」

## 意图

满态那一族（§6.141 / §6.142 / §6.143）量的是「很多」，而它们量的每一个数都是**两个相邻
元素之间**的数：节奏、卡间面、组计数。N=1 时一个间隔都没有，N=0 时连组都不存在。
这两格此前**没有任何 pin**，而它们恰好是最容易长出一条「最后一个元素特例」的地方
（最后一行不画分隔线 / 最后一张卡不画下边 / 空态头上还挂一个「已安装 0」）。

**为什么现在做**：P13-fx「仍待」第 1 条 `140-5` 需拍板，替代路径 = 通用队列；
「满态」三格已收口，剩下的同类问题只有「N 很小」这一侧。表面 = 集成页已装列表
（`internal/settingsui/settingsui.go` 的 `Integrations` 组 + `rows.go:103`
`sectionGroupPadded` 的 `Gap(Space(2))`）。

**这轮为什么让它更轻、更有空间感**：空间感是**面与面之间那段空气**的算术，而那段空气
只在「有两个东西」时才存在。N=1 的页面上没有空气可数——所以这一格要守的不是间距，
而是**边界本身仍然被画出来**：一张卡即使后面什么都没有，它的下沿也仍是两行（描边 + 影），
一个空列表即使一张卡都没有，它画的也是空态而不是一个「已安装 0」的空组。

两处量出来的事实：

1. **卡的下沿是 2 行，不是 1 行**：一条 1px 描边（`{216,216,216}`，三通道相等 = 纯线色）
   + 它自己那一条影（`{216,216,217}`，带着卡面 230 的蓝通道）。所以「卡高 179」里
   上沿 2 行、下沿 2 行；卡与卡之间那 8 行是**页面的面**，被这两对夹住。
2. **N=0 不画组**：这一页的「没有」是空态，不是「Installed 0」——组标题与计数节点
   整棵都不在（`tt.Find` 找不到 `Installed`）。
