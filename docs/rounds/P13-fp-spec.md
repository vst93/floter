# P13-fp 规格：picker 的地板之上，得有一条天花板

**意图**：P13-fo 把调色板 picker 从 `Width(220)` 改成 `MinWidth(220)`——「220 是地板不是
上限」，长值不再被省略号切。那句话只说了**一半**：这一行有两个孩子，picker 右边是那块
缩微终端（`palettePreview`，固定 `Space(37)` + `Shrink(0)`）。地板没有天花板，值一长，
picker 就把预览块顶出行外。这一轮给它补上另一半：**长值在自己的盒子里收口，预览块一个
像素不挪。**

为什么现在做：P13-fo 报告「仍待」第 1 条 = `palettePreview` 自己的宽度来源（同一张卡的
下半块）。量它的过程中发现：预览块从来不会切自己的字（见下），真正的病在它**左边**——
一个上一轮刚放开的盒子会把它推走。

出厂九个调色板名（最宽 `High contrast` 80px）碰不到这条线；但 `paletteRow` 的标签表是
**参数**（`i18n.Settings.Palettes`），调用方可以传任意 `Option.Label`——P13-fo 自己就是
用 55 字标签证明地板生效的。被推出去的偏偏是**预览块**：它才是这一行存在的理由
（R43，用户要看见调色板长什么样）。

同一批测量顺带回答了 P13-fo 留下的那个问题（「预览块的 `Space(37)` 会不会在更小台阶上
切字」）：**不会**。三个台阶 × 深浅，最长的那句 `floter --version` 距块内沿
25.6 / 26.8 / 29.0 / 32.2px，永远够用。
