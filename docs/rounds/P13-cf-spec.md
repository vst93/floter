# P13-cf 规格：启动器结果列表的满态收口——先量，量下来它已经读同一条规则

上一轮（P13-ce）「仍待」第 1 条。起点 `5f6ceb73`（P13-ce）。

## 意图

P13-ce 的「仍待」写着：

> 启动器**结果列表**（`launcher.go` `rowBody`）读同一条规则，但它的页头是字段行
> （绝对定位、不透明），滚动体在它下面——**先量**它有没有同一道「呼吸被内容吃掉」，
> 再决定要不要照这一轮改。

**量完了，结论是「已经对」**：这一页的 19px 空气**在裁剪之外**，任何滚动位置上都是零墨。
这一轮因此是**先量后不改**（同 P13-bm §6.31 / P13-bq §6.35 的先例），交付的是
**一条判据 + 三条 pin**，而不是一次像素改动。

## 量到了什么（720×488 帧，30 个应用、查询 `app`）

**第一次量错了，记在这里**：先按 P13-ce 的办法量「字段带最后一行墨」，得到 **19px**
（y=40 → 60），和捕获输出页的数一模一样，差点就写成「两张卡同值，收工」。错在
`contrastIn` 的判据——它把「框内最偏离面色的像素」当墨，而字段块的最后一笔是一条
**整行同色**的发丝线（`launcher.go` 的 `ui.Box(...).Top(fieldRow-1).Height(1)`，
`HairlineSoft`）：整行都是 239，它自己就是那一行的「面色」，于是偏差算出 0。
改成读卡片左侧 gutter（x=5，除了块自己的填色就只有那条线）才看见它。

| 事实 | 数值 | 出处 |
|---|---|---|
| 字段块的发丝线（= 块的最后 1px） | **y=55**（`fieldRow-1`，深浅同值） | gutter 剖面 |
| 列表裁剪盒（= `a.listRect`） | `{X:0 Y:60 W:720 H:383}` | `a.listRect` |
| 发丝线 → 裁剪上沿 | **4px**（56..59 全零墨） | gutter + 逐行 `contrastIn` |
| 首行盒 | `Y=60`，**与裁剪上沿逐像素重合** | `a.rowRects[0]` |
| 滚 0 / 10 / 20 时，56..59 带内墨 | **0 / 0 / 0**（深浅两套） | 逐行剖面 |
| 顶边被折边切一半的行（露出 0.50） | 墨 **117 / 226**（理论 113）；深 **107 / 214**（理论 107） | 折边比例 pin |
| 下沿被切的行（露出 0.57） | 墨 **130 / 226**（理论 130）；深 **123 / 214**（理论 123） | 同上 |

四条判据：

1. **呼吸不滚**（成立）：发丝线到裁剪上沿那 4 行，在任何滚动位置上墨为 0。
2. **归属正确**（成立）：列表自己的上 padding 是 0（`Padding(0, Space(2), Space(0.5)+statusBand, Space(2))`），
   那 4px 是页面在流里让出来的 `ui.Box(...).Height(listEdge)`（`launcher.go:1446`）——
   在裁剪**之外**，所以内容吃不掉它。**这正是 P13-ce 给捕获输出页补上的形状**，
   启动器在 P11-bj 就已经是这个形状（当时为的是另一个理由：字段行不再是不透明遮罩）。
3. **两端成对**（成立）：`foldAlpha` 对顶边与下沿读同一个函数、同一对盒子（`a.listRect`
   与 `a.rowRects[i]`），顶边没有例外分支；实测比例 117/226 与 130/226 都落在
   可见比例 ±12.5% 以内。
4. **两个数不一样**（新发现，需拍板）：同一条规则，启动器是 **4px**、捕获输出页是
   **16px**（`output.go` 的 `header := t.Space(4)`）。启动器那个 4 是高度链里的
   `breathUnits`（`height.go:24`，`chrome := (fieldRowUnits + breathUnits + …) * spacing`），
   把它抬到 4 单位会让窗口长 **12px**——**高度链是红线**，所以这一轮不改，写进
   `.pending-bugs.md` 的「需用户拍板」。

## mutation 计划（≥2 条，实跑）

- **M1 · 把那 4px 挪进列表的 padding**（复现 P13-ce 的缺陷类）：`launcher.go` 的
  `ui.Box(...).Height(listEdge)` 改成 `Height(fieldRow)`，列表 `Padding(0, …)` 改成
  `Padding(t.Space(breathUnits), …)`。预期：**空气**那条臂变红（4px → 0px），
  首行盒与裁剪上沿的重合也变红。
- **M2 · 折边在顶边失效**：`rowBody` 里 `foldAlpha(a.listRect, a.rowRects[i])` 换成
  「顶边不折」（把传给 `foldAlpha` 的视口上沿抬到 0）。预期：**顶边按比例退后**变红。
- **M3 · 折边比例只对一端生效**：`foldAlpha` 里把 `visible/box.H` 换成 `visible/(box.H*0.5)`
  之类的单边偏置会同时打红两端——用来说明「同一个公式」这条 pin 真的读了两端。
