# P13-ek · 设置页的分组标题，比它自己下面那些卡贴得还紧

选题：`docs/liquid-glass.md` §6 差距表里**唯一**剩下的 `未开始` 行 **105-3**——「设置页每个
分组标题下面的那 8u」。它是 §6.105（P13-ej）同一格的另一半：浮层那一半已经把这一格抬到
`Space(4)`，设置页这一半还停在 `Space(2)`。

## 意图（一句话）

设置页每个分组标题离它自己第一张卡只有 **6.7~6.9px**，比同一组里两张卡之间的 **9px 还紧**
——标题读成「又一张卡」，分组在 z 上不存在。这一轮只把**这一对**的空气抬一整档（+8u），
标题与它下面那张卡之间变成 14.4px，与浮层里同一格逐值相同。

## 先量（证据，`PageGeneral` 720×2000，深浅同值）

量法：`cardTopGap`（既有的取景函数）——标题**文字节点**的底边往下扫，第一处非地面色像素就是
卡的顶边。文字节点的盒子不含行盒的空白，所以这个数是「标题墨 → 卡的上边」。

| 组 | 改前 | 改后 |
|---|---|---|
| Appearance | 6.7 | **14.7** |
| Window | 6.7 | **14.5** |
| Menu bar | 6.9 | **14.5** |
| Terminal | 6.7 | **14.1** |
| Material | 6.9 | **14.1** |

同一组里**卡与卡之间**是 `Space(2.5)` = **9px**（`TestTheMaterialSectionKeepsItsOwnSpacing`
的 `first card to second card`）。改前 6.7 < 9：标题比卡更贴卡。

墨上同一个结论（`Window` 组——它是唯一一组卡里只叠「标签 + help」、没有宽控件的组；
`Appearance` 的卡里有主题色块，`Menu bar` / `Terminal` 有它们自己的宽控件，整列读不了）：

| 行 | 改前墨带（y） | 改后墨带（y） |
|---|---|---|
| 分组标题 | 451..461 | 458..468（页面整体因第一组 +7.2 而下移） |
| 第一行标签 | 486..498 | 501..513 |
| 它的 help 行 | 505..516 | 520..531 |
| 第二行标签 | 538..548 | 553..563 |

- **标题 → 第一行标签：24px** → **32px**
- **上一行 help → 下一行标签：21px** → **21px**（同一张卡的行距，未动）
- 差：**3px** → **11px**

同一格在浮层里（§6.105）改后是 **32px 对 22px**：两个面现在读同一个数。

## 落地项（逐条：位置 → 现状 → 应改成）

| # | 位置 | 现状 | 应改成 |
|---|---|---|---|
| 1 | `internal/settingsui/rows.go:180` `sectionHeadingInline` 的 `Padding(0, Space(0.5))` | 标题行只有左右内边距；标题 → 卡 = 框架的 `Space(2)` = 7.2px | `Padding(0, Space(0.5), Space(2), Space(0.5))`：**下边**加一整档 8u，标题 → 卡 = `Space(4)` = 14.4px |
| 2 | `sectionGroupPadded` 的 `Gap(Space(2))` | 7.2px | **不动**——它同时是「卡 → 组注」那一对，那一对是「同一块」（§4.3 的相邻一档），不许跟着抬 |
| 3 | `internal/settingsui/materialspacing_test.go` | 断言 heading → first card = `Space(2)` | **V 重定基线**：旧值 `Space(2)` → 新值 `Space(4)`；其余三条 gutter 的断言一个字节不动 |
| 4 | `internal/settingsui/sectionheading_test.go:54` | `action bottom == rowBox.Y+rowBox.H` | **V 重定基线**：`flex-end` 对齐的是**内容盒**的底，行的外框现在多一条 `Space(2)` 的下内边距 → 断言改成 `rowBox.Y+rowBox.H-Space(2)` |
| 5 | 新 pin `internal/settingsui/sectionheadingair_test.go` | 无 | ①五组的标题 → 卡 = `Space(4)`±1.5；②它比卡与卡之间松 ≥4px；③墨上 `Window` 组标题空气比行空气多 ≥6px；④第一组标题仍在 y=130（这一轮的空气属于标题**下面**）；深浅两套 + opt-in 出图 |

**为什么加在标题的下边，而不是把整列的 `Gap` 抬到 `Space(4)`**：`section` 的组列里有三个
孩子（标题 / 卡列 / 组注），`Gap` 是**三对共用**的一个数；抬它会连「卡 → 组注」一起抬，而那一对
是「同一块」（§4.3）。加在标题下边，只有「标题 → 卡」这一对变，组注与它的卡仍是 7.2px——
这也正是 P13-ej 的注释里警告过的「一个 gap 参数 = 第二个刻度回来了」的相反做法。

## 代价（写在这里，不藏）

每一组高 **+7.2px**（`Appearance` 297 → 304、`Window` 240 → 247、`Menu bar` 170 → 178、
`Terminal` 355 → 362、`Material` 380 → 387）：整页往下长 36px，第二组以后的 y 全部 +7.2。
第一组的标题仍在 **y=130**、页头一个像素没动。组与组之间的 22px（`pageColumn`）没变。

## 行为契约零改动

高度链、键盘模型、会话管理、设置写回、i18n 文案、命令接线：**一个字节没动**。
这一轮只改一条内边距与两条 pin 的参照系。
