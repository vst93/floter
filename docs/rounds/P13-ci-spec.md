# P13-ci 规格：捕获输出页的行，标题和副标题是同一个字重

## 意图

同一张卡里的两张列表（启动器的结果列表与捕获输出页的列表）对「标题 / 副标题」
给了**两套不同的排法**：启动器 `580 / 510`（`launcher.go:2647` / `2678`），
捕获输出页 `400 / 400`（`output.go` 的 `drawOutputRow`）。于是一份只有
`kind:"status"` 便条的列表里，标题与副标题**同墨同重**（实测浅色 113 / 113），
读起来是两行等价的句子，而不是「一行标题 + 一行说明」。

为什么现在做：P13-ch 的「仍待 1」把这一族点出来了（便条行的图标板叠了两道淡），
本轮先量那块板——**量下来它没病**（见下「量到的东西」），于是顺着同一族往上
读到行内文字：板没病，行没分档。

## 量到的东西（先量，量完再改）

量法：`runListOutput` 渲染一张两行的列表，读第二行（静息行）的像素剖面，
x 取 `54..500`（标题列右侧、行尾槽左侧），逐行取**离地面最远的墨**。

| 读数 | 浅色 | 深色 |
|---|---|---|
| 便条行 · 图标板面 vs 行地面 | 242 vs 253（**11**） | 38 vs 23（**15**） |
| 门行 · 图标板面 vs 行地面 | 235 vs 253（18） | 47 vs 23（24） |
| 便条行 · 标题墨 / 副标题墨 | **113 / 113** | 同档 |
| 门行 · 标题墨 / 副标题墨 | 24 / 113 | 同档 |

结论一：`DimFace` + `Opacity(0.62)` 两道淡**没有**把板淡没——还剩 11（浅）/ 15（深）
级，仓库自己的门槛是 8（`notecursor_test.go` 的 `channelGap >= 8`）。**不收成一道**，
这条候选作废，写进报告。

结论二（本轮做）：便条行的标题与副标题**同一个墨、同一个字重**。门行至少还靠墨
分了两档（24 / 113），便条行两行都是 `TextMuted`，字重都是 400——`docs/liquid-glass.md`
§4 的「层级靠面差 + 字重，不靠画框」在这里没有落地。

## 逐条落地项

位置：`internal/launcher/output.go` · `drawOutputRow` 的 `style.Children`。

1. 标题 `ui.Text(c, row.Title)`：现状 `FontWeight` 未设（400），`chosen` 时 700。
   应改成 **580**（与 `launcher.go:2647` 的列表标题同一档），`chosen` 仍 700。
2. 副标题 `ui.Text(c, row.Subtitle)`：现状 400。应改成 **510**（与
   `launcher.go:2678` 同一档）。

**只动字重，不动墨、不动字号、不动尺寸**：`TextMuted` / `Text` / `TextSecondary`
的取值一个字节不改，行高、padding、gap 一个字节不改。

## 行为契约零改动红线

- 不碰 `outputRowRects` / `foldAlpha` / 视口盒（P13-ce / P13-cf 的收口）。
- 不碰 `selected` / `chosen` / `row.Runnable()` 的语义（P13-cg 的只读游标）。
- 不碰数字徽标、动作栏、键盘模型、`outputText()` 的复制内容。
- 不碰启动器列表（它是参照物，不是本轮的对象）。

## mutation 计划

- **M1**：标题字重 580 → 400（回到旧值）→ `rowweight_test.go` 的「便条行标题的墨量
  必须高于副标题」变红。
- **M2**：副标题字重 510 → 400 → 同一条臂的「副标题墨量」侧变红（或差值跌破阈值）。
- **M3**：把 580 换成 400、把 510 换成 700（把两档调反）→ 同一条臂变红。

## 判据（写进合约 §6.52）

字重是**墨级差看不见的那一半**（P13-ch §6.51 的教训）：同一 token 下 400 与 580 的
最暗像素同值，分得开的是**墨量**（`255 - R` 在字带上的和）。所以本轮的 pin 只能量
墨量，不能量最暗像素。
