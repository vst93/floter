# P13-gh · 卡里那些规则线占几行（报告）

**一句话**：整幅宽的分隔线是**一行整值**（浅 63 级 / 深 57 级，两侧逐值相等，斜坡 0 列），
「半行」只属于落在 x.5 帧上的**控件内线**，不属于页面规则线——本轮零像素改动，只把这件事
钉成三条判据。

- 规格：`docs/rounds/P13-gh-spec.md`
- 合约：`docs/liquid-glass.md` **§6.153**（新增）
- 台账：**V 0 / B 0 / S 0**
- 出图：`/tmp/p13gh/floter-P13-gh-general-{light,dark}.png`（opt-in
  `FLOTER_DUMP_HALFROW=1 go test -run TestDumpP13GhHalfRows ./internal/settingsui/`）

## 1. 量尺（不依赖颜色的分类）

对每一行 `y`、每一列 `x`：`before = lum(y-1) − lum(y)`、`after = lum(y) − lum(y+1)`。

- **异号**、两侧都 ≥ 4 级 → **一行整值的线**（这一行是极值，前后两行在它同一侧）；
- **同号**、各 ≥ 2 级、和 ≥ 8 级 → **两行各半的斜坡**（`y` 与 `y+1` 各走一半，中间没有极值）。

整帧 660 列 × 1400 行逐像素分类，按行统计「多少列说它是线 / 多少列说它是斜坡」。

## 3. 防误判（下一轮不要当缺陷去修）

- 卡片**上沿**在这把尺子上读作「斜坡」，但它是 §3 的两条线叠出来的层次：
  浅 `740 → 649 → 706 → 688`、深 `119 → 122 → 152 → 172 → 176`（窗外地 → 发丝边 → 冠 → 面）。
  「两侧逐值相等」正是把分隔线与卡片边分开的那一步。
- 页尾 1385–1400 是一段**多行渐变**（§6.141 / §6.145 的软边），不是线。
- 28u 控件的 1px 内线本来就跨两行（`litpair_census_test.go:43-47` 早有记载）。

## 4. 一个反直觉的实测（M2 预期红，实际绿）

把分隔线整条挪 **0.5 DIP**（`Height(1)` 那枚 `Box` 从 `.MarginX(inset)` 改成
`.Margin(0.5, inset)`）→ 九条线的像素**一模一样**，三条判据全绿。结论：**`Box` 的 1px 边
由渲染器按设备行吸附**，所以「半行」只发生在**落在 x.5 帧上的内嵌线**（`InsetShadow`），
不会发生在布局盒上。这一条比原计划更有价值：它把「糊」的机制收窄到控件内线一处。
