# P13-dx 规格：同一张卡两张列表的副标题差 6 级 —— 差的不是墨，是字号

## 意图

`P13-dw`「仍待」第 1 条 = `docs/liquid-glass.md` §6.86 表里「产品的墨」那一行（`dg-l-4`）：
捕获输出页选中行的副标题比启动器列表选中行的同一句话暗 **6 级**（浅 119 / 深 112 对 125 / 118）。

本轮**先量再改**，量出的结论把这一行的诊断改掉了：两支副标题的**墨是同一个 token**
（选中档都是 `tokens.TextSecondary`，静息档都是 `t.TextMuted`）。6 级的差来自**字号**——
这一页把副标题画在 `t.FontSize - 1`（= **9.8px**）上，而启动器列表画在 `t.FontSize`
（= **10.8px**，即阶梯上的 `tokens.Body`）。同一个 token 在 9.8 上**覆盖不到自己的墨**：
这一页的副标题镜到的是 119，而 `TextSecondary` 自己离面的距离是 **125**（浅）/ **118**（深）
—— 也就是说「选中的副标题」在这一页**从来没画出过它自己的颜色**，永远浅 6 级。

为什么现在做：§6.74 把这条列为 `de-10`，当时卡在「夹具量的是库存尺」上（`73-5`）；
`P13-dq…dw` 已经把启动器的取景收口到出货尺（`renderShipped` / `listOutputShipped`），
本轮把这条解封。而且 `t.FontSize - 1` 本来就不在字阶上（`Caption` 是 **9.9**，它写 9.8）——
P13-de 的判据「小字是阶梯上的档，不是「比正文小一档」」这一页还没吃到。

## 先量（同一台建机，出货尺 `720×439`，改前）

| 读数（墨距 = 字带里离行面最远的像素，§6.51 判据 2） | 浅色 | 深色 |
|---|---|---|
| 捕获输出页 · 选中行 副标题（`FontSize-1` = 9.8） | **119** | **112** |
| 启动器列表 · 选中行 副标题（`FontSize` = 10.8） | **125** | **118** |
| 捕获输出页 · 静息行 副标题（`TextMuted` @ 9.8） | **115** | **115** |
| 启动器列表 · 静息行 副标题（`TextMuted` @ 10.8） | **118** | **118** |
| `TextSecondary` 自己离**选中行面**的距离 | 125 | 118 |
| `TextMuted` 自己离**静息行面**的距离 | 118 | 118 |
| 行盒高（选中 / 静息） | 42 / 42 | 42 / 42 |

**两条结论**：① 这一页的副标题（9.8）与启动器列表的副标题（10.8）读同一个小数点的
**两个寄存器**；② 9.8 上这份墨**够不到 token 自己的值**（119 < 125、112 < 118）——
小到覆盖不足的字不是「浅一档的墨」，是「没有画出这个墨」。

同一份量在**库存尺**（`render` / `runListOutput`，本页两个臂今天用的尺）上：
两处都是 131 / 111 / 140 —— **差 0**。所以这条 pin 一直是绿的，它量的是 app 不会画的帧
（§6.86 的同一课：`dg-l-4` 的红串只在出货尺上现形）。

## 落地项

1. **`internal/launcher/output.go:988`**：`FontSize(t.FontSize - 1)` → `FontSize(tokens.Body)`。
   `tokens.Body` 在出货步子上就是 `t.FontSize`（10.8），多写一个 pixel 都不多；
   改的是**这个数是阶梯上的一档**，不是一个减一。（行盒随之 42 → **44.8**，见下。）
2. **`internal/launcher/outputsubtitle_test.go`**（两个半边的取景）：
   `runListOutput` / `render` → `listOutputShipped` / `renderShipped`，
   出图与 pin 量同一帧；`textBand` 的 x 起点 `54` → `int(54 × designUnit())`（= 48，
   §6.87 的判据：参考写 54u 就得乘 `designUnit`）。
3. **同文件 ②③ 两臂的 `±4` 容差带删掉**，改精确相等（改后实测两支都是 125 / 118，
   静息两支都是 118 / 118，差 **0**）。§6.92 的判据：同族 pin 的比较器不许带容差带。
4. 新增一臂 **⑥「副标题够得到自己的墨」**：选中档读到的墨距必须等于 `TextSecondary`
   在这个面上应有的距离（浅 125 / 深 118），静息那一句同理（118）。这条钉的是**字号**，
   ② 钉的是**两条列表相等**——两处一起漂，② 是绿的，⑥ 是红的。
5. 注释：`outputsubtitle_test.go` 文件头那段落伍的「±4」「131 / 111」换成出货尺读数；
   `output.go` 的 P13-cj 注释补上 P13-dx 这一段（9.8 不是墨，是字号）。

## 行为契约零改动红线

- 高度链：**窗口高度链不动**（`Geometry.Height` 读的是启动器行的行盒，输出页的行是内容撑的、
  在滚动视口里）。输出页行盒 42 → 44.8 是**这一页行内容自己的**高度，视口按裁剪盒算，
  行数由滚动决定，与窗口高度无关。
- 键盘模型、会话管理、设置写回、i18n 文案、命令接线：零改动。
- 只改这一页行副标题的**字号寄存器**与它的夹具。

## mutation 计划（实跑，红 → 还原 → md5 → touch 复跑）

- **M1**：`tokens.Body` 退回 `t.FontSize - 1`。预期 ②③ 两臂都红（-6 / -3），⑥ 红（119 ≠ 125）。
- **M2**：把 `TextSecondary` 换成 `t.Text`（同页两处一起），预期 ① 红（差 < 60）与 ② 红。
- **M3**：取景退回 `render` / `runListOutput`（库存尺）。预期：红串**换形状** ——
  库存尺上两支只差一档以内（`-1 levels (130 vs 131)` / `139 vs 140`），旧 `±4` 的容差带
  会把这条真缺陷整个吞掉。这条用来证明「库存尺 + 容差带 = 看不见」，即本轮换尺是必要的。
