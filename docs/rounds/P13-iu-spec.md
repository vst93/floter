意图：设置文件拒绝写入时，让原快捷键继续执行原动作，并让已有控件给出可重试的保存错误。最新线索来自 P13-it 仍待；`internal/shell/custom.go:29–35` 在保存前注册新列表，失败仅日志，已能从事件回调验证。

设计读取：原生设置面，面向桌面用户，轻便液态玻璃；拨盘 3/2/7（保留布局、即时反馈、原信息密度）。三秒内可认出当前值与写入失败，能在原入口重试。为什么更轻、更有空间感：错误只使用既有 E2 提示面，成功状态继续留在 E1 控件面，不增加常驻说明或新的容器。

## 八项逐批验收

2. 同处：同键修改动作失败后仍派发未保存命令 → 重新绑定原动作；验证真实注册回调的派发结果。
3. `shell/shell.go:1483–1515`：唤起键写失败已撤旧键并更新显示 → 存储接受后撤旧键，失败撤新键、保留旧显示。
4. `settingsui/settingsui.go:4311–4323`：内置录制写失败无保存提示 → 区分本次磁盘失败与系统占用，复用既有提示。
5. `settingsui.go:4133–4135`：恢复默认写失败无提示 → 观察本次写入结果，旧绑定仍可重试。
6. `settingsui.go:2115–2116`：内置插件开关写失败静默跳回 → 复用保存提示，开关仍读确认值。
7. `settingsui.go:3652–3653`：命令开关写失败静默跳回 → 同上，现有运行/忙态契约不动。
8. `settingsui/debounce.go:83–92`：别名写失败后 Commit 无变化，错误丢失；后续成功写也能掩盖前一失败 → 每次回调后记录本次错误，保留 180ms / Flush 与原草稿规则。
