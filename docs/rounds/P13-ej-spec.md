# P13-ej · 分组标题离它自己的第一行，只比两个字段之间多 1px

选题：`P13-ei`「仍待」第 1 条的兜底那一半——`§6.104` 的 `104-2` 是**需拍板**（动几何），
于是取通用队列的**间距节奏**：`internal/launcher` 与 `internal/settingsui` 各量一次
「同一角色」的间距。量出来的结果是：**同一个角色（一行名字 → 它下面那句灰线）在两个面上
是同一个数（9px 空气）**，没有差异；真正错的是**分组标题与它自己那一行之间**那一格。

## 意图（一句话）

分组标题是这一块面上唯一的「编辑标记」，它离自己第一行的空气只比两个字段之间多 **1px**
——读者看到的是「又一行」，不是「新的一组」。这一轮只把这一格抬到刻度上（§4.3 的
「一个新的东西抬开一整档」），别的什么都不动。

## 先量（证据，`pluginSheetFrame`，出货尺 720×600，深浅同值）

墨带用「本行最远像素离本行中位亮度」判定，阈值 40（卡面自身的边只有 17 级，
行发丝在深色档 43 级，文字 94~222 级），窗口 = 夹具自己的 `sheetBand()` 的**文字列**
（带宽的左侧四分之三；控件槽右对齐在带的远端，`sheetFieldSlot` 的 `MinWidth(Space(12))`），
所以复选框那根实心竖条不会把 help 行并进标签行（§6.102 的教训：探针的窗口来自布局，不是常数）。

| 行 | 改前墨带（y） | 改后墨带（y） |
|---|---|---|
| 浮层的名字 | 67..78 | 67..78（**未动**） |
| 第一个分组标题 | 100..109 | 100..109（**未动**） |
| 第一个字段标签 | 134..146 | 142..154 |
| 它的 help 行 | 153..164 | 161..172 |
| 第二个字段标签 | 188..200 | 195..207 |

- **分组标题 → 第一行标签：24px**（改后 **32px**）
- **上一行的 help → 下一行标签：23px**（改后 **22px**）
- 差：**1px** → **10px**

同一角色的横向对照（证明不是「整块面都太挤」）：启动器结果行里「标题墨 → 它的灰线墨」
是 **9px** 空气（`rowRects[0]` h=36，墨带 95..104 / 114..121）；浮层字段里同一对是
**9px**（153−146−1 = 6？见下）——两处**同一档**，说明这一族本身是对的，错的是分组那一格。

> 备注：字段标签→help 的空气在窄窗里是 6px，在整带里被复选框并成 9px（同一对墨的两端
> 差在三行抗锯齿上）；启动器那一对是 9px。三个数落在 6~9px，属同一档，不是本轮的对象。

## 行为契约零改动红线（逐条核对）

- **高度链**：`Geometry.Height` 读的是启动器行的行盒；浮层是 scroller，`MaxY` 是内容高度，
  不参与窗口高度链 → 不动。
- **键盘模型 / 会话管理 / 设置写回 / i18n 文案 / 命令接线**：一个字没改（本轮只有 1 行 `Gap`）。
- 顶边：名字仍在视口顶第 **11** 行，第一个分组标题仍在第 **44** 行（§6.72 的顶边余量
  0.2px 那条 pin 不受影响）。
