# P13-w 规格：捕获输出页的折边——同一族，同一个函数

## 意图

**把 P13-v 的折边规则接到捕获输出页上，并且证明它在这一页真的看得见。**

为什么现在做：P13-v 的「仍待」第 1 条就是这一条（`output.go` 的 `outputBody`
同族硬切）。但先量过才发现——**这一页的折边今天根本没有墨可淡**：

| 位置 | 现状（实测） |
|---|---|
| 视口 | `outputListRect = {X:0 Y:102 W:720 H:386}`，折边 y=488 |
| 折边上的行 | `outputRowRects[9] = {X:8 Y:478 W:704 H:40}`，`share = 0.250` |
| 这一行的文字盒 | `{X:54 Y:487 W:607 H:1}` —— 被切到 **1 px** |
| 那 1 px 里的墨 | `darkest = 253`，暗像素 **0** 个（它就是面板的面，不是字） |
| 往上 4 px 的整条带 | y=484..490 `dark-pixels = 0`，`darkest = 253` |

原因是 40u 的行盒里，文字盒只从 y+9 开始（`{Y:478+9}` → 487），而折边正好落在
487——**切在字盒的前导里**，一个字都没露。于是 P13-v 的 `foldAlpha` 若原样接过来，
像素上是**空操作**：一行 0.25 可见的行，墨本来就全是 253。把「退后」接上一个
什么都不淡的折边，等于交一份假动作。

同一页**上半**的折边反而是真的硬切：滚到中间之后 `outputRowRects[3] =
{X:8 Y:96 W:704 H:40}`，`share = 0.850`，而它被视口上沿 y=102 切掉 6 px——实测
y=111..121 那一条有 `darkest = 25` 的**墨**（`Row 3` 的字母），从 111 到 121
一刀断在 y=122（`darkest = 235`）。这是用户点名的「界面坏了」那一类。

再往上量一层，**这一页折边上的墨不是字，是图标板的顶边**：行盒 `{Y:478}`、
28u 的板从 `Y:484` 起，所以可见的 10 px 里有 4 px 是板——实测 y=484..487
`darkest = 235`（板面），字一个都没有。

所以这一轮**不是**空操作（我先前在草稿里判过「空操作」，实测推翻）：折边行今天
是「一块板的顶边以满墨压在折边上」，接上 `foldAlpha` 之后它会退到 248。
**但它也不是 P13-v 那个样子**——那边折边切在字母中间，退后能读到半个字；这边
折边切在板的上沿，退后只剩一道几乎看不见的弧。两页共用一条规则，读数不同。

于是落地就一条，但 pin 要能分辨「退后」与「没退后」：**同一个折边行，露出得越多
墨越深**（0.25 可见 vs 0.75 可见），而不是「折边行比整行浅」——后者在改之前
就成立（235 < 25 是反的，板本来就没字深），钉不住任何东西。

## 判据（这一轮为什么让它更轻 / 更有空间感）

P13-v 给「越过折边」定的话是：**折边之外的东西是退后，不是被切**。捕获输出页
是同一张卡里的另一张列表，今天它没有这句话——滚到中间时 `Row 3` 的字母在
y=122 一刀断掉，读起来是渲染坏了，不是「上面还有」。接上之后，越过折边的那一行
按它露出的比例退后，折边自己成为「还剩多少」的刻度。这正是轻便液态玻璃的
深度语汇：**用面与墨的退让表达 z，而不是拿背景色画一条渐变遮罩**（§0 禁）。

## 逐条落地项

动手前逐条核过真实行号（HEAD = `23404b42`）。

### W-1 · 折边退后接到 `outputRow`

- 位置：`internal/launcher/output.go` `outputRow`（`:590`），行样式在 `:634`
  （`style := ui.Row(c.Key(row.ID))...`），行盒记在 `:686`
  （`a.outputRowRects[i] = style.Bounds()`）。
- 现状：`outputRow` 只在 `row.Status || row.Disabled` 时给 `iconPlate` 0.62
  （`:654-657`），整行**没有**任何折边退后。折边行 `share=0.25` 与整行可见行
  逐像素相同（除被裁掉的部分）。
- 应改成：在 `style.Children(...)` **之前**下发一次行墨
  `min(静息档, foldAlpha(a.outputListRect, a.outputRowRects[i]))`。静息档在这一页
  是 1（与启动器列表不同，这里没有 0.92 的历史档），所以实际是 `foldAlpha`。
- 为什么必须在 `Children` 之前：`Bounds()` 是**上一帧**的盒子（与 `rowBody` 同一条
  时序，见 `launcher.go:2336` 的注释），所以读上一帧的 `a.outputRowRects[i]` 与
  `a.outputListRect` 是自洽的；`style.Opacity` 必须在子树建出来之前设置，
  否则框架按上一帧的 opacity 画这一帧。

### W-2 · 折边落在前导里也要说话（本轮的新判据）

- 位置：同 W-1，`foldAlpha` 的调用点；纯函数本身不动。
- 现状：`foldAlpha` 只按**盒子**的可见比例算。捕获输出页的 40u 行盒里，文字盒
  从 y+9 开始（实测 `{Y:478}` 的行，字盒 `{Y:487}`），所以「露出 10/40」与
  「露出 0/40」在像素上可能是同一个 253。
- 应改成：把**行内第一个有墨的像素**这一件事交给行自己——`outputRow` 在算完
  `foldAlpha` 之后再叠一层 `inkFold`：折边相对**文字盒**（而不是行盒）的可见比例。
  两个比例取更暗的那个。文字盒是这一帧现成的（`title` 元素的 `Bounds()` 也是上一帧，
  与行盒同一时序）。
- 为什么不是改 `foldAlpha`：`foldAlpha` 是 P13-v 的 pin（`fold_test.go:138` 的
  `TestFoldAlpha` 表钉着「cut at the bottom = 23/40」），改它会把启动器列表的
  折边基线一起挪掉——那是 V 类改动，而这一轮**不该动**那边已经验过的像素。
- 边界：文字盒还没量出来（首帧 `H<=0`）→ 不叠，返回 1（与 `foldAlpha` 同一条
  「首帧不淡」）。

### W-3 · 动作栏不参加（同 P13-v 的边界）

捕获输出页的页脚（`outputFooter`，`:272`）是 `ui.Row(...).Shrink(0)` 的钉住带子，
不是 `ui.List` 的行，本来就不经过 `outputRow`——这一条**不需要代码**，但要有一条
反向 pin 钉住「页脚不被淡」，免得以后有人把它挪进行循环（P13-v 的变异 M3 就是
这么抓出来的）。

## 行为契约零改动红线

- 高度链：`outputBody` 的列/`MinHeight(0)`/`header` 一律不动。
- 键盘模型：`outputRow` 的 `Clicked`/`output.Selected`/编号下发一律不动。
- 会话管理、设置写回、i18n 文案、命令接线：零改动（本轮不碰 `i18n`、不碰
  `extensions`、不碰 `termsession`）。
- 只改墨：本轮新增的只有 `Opacity`。
