# P13-ac 报告：浮层那一档沿透明度滑块的两端（先量，不改）

**这轮为什么让它更有空间感**：空间感是「差值」，而差值是随**框的厚度**变的。这一轮把
elevation 阶梯沿 `main_opacity` 滑块 10%→100% 逐档量了一遍，回答任务书写成假设的那个数，
并把答案钉住——于是「面档不跟着框一起变淡」从此是一条**有测试守着**的规则，而不是一句口号。

## 量出来的结论（`docs/liquid-glass.md` §2.1 已落表）

| 滑块 | 底 `TintAlpha` | 浮 `FloatAlpha` | 浮−底 | 相对 |
|---|---|---|---|---|
| 10% | 0.10 | 0.20 | **0.10** | **2.00×** |
| 25% | 0.25 | 0.35 | 0.10 | 1.40× |
| 47%（默认） | 0.47 | 0.57 | 0.10 | 1.21× |
| 70% | 0.70 | 0.80 | 0.10 | 1.14× |
| 90% | 0.90 | 1.00 | 0.10 | 1.11× |
| 100% | 0.98 | 1.00 | **0.02** | 1.02× |

任务书的假设（「10% 端差 0.10 太弱 → 按 alpha 缩放面档」）**不成立**，方向是反的：

- alpha 差是**常数** 0.10，所以相对抬升在低端**最大**（10% 时浮层是底的两倍）。
- 浮层的 fill 是 `#18191D` / `#FCFCFE`（近黑/近白），框越薄透出的桌面越多，**像素**差越大。
  按 alpha 缩放会把两档拉平 —— 正是用户说的「所有东西挤在同一个 z 平面上」。
- 真正塌的是**顶端**：`SolidTop = 0.98` 封底、`min(1, …)` 封浮，差从 0.10 掉到 0.02。
  这一档的浮层本来就不靠 alpha 分家（§2 判据 3 的两层影 + `EdgeHighlight`），
  而把底压到 0.88 换回 0.10 会改掉 `main_opacity` 的承诺（滑块即 alpha 真值）= 行为契约。

**改判两条 `故意不做`，写进 §2.1**（附理由与数字），零产品像素改动。

## mutation（3 条实跑，全部变红并逐字节还原）

- **M1** `floatStep 0.1 → 0.03`：`floatStep = 0.03, want the shipped 0.1` +
  `10%: the float lifts 0.030, want 0.100` → 红。
  **第一次没红**：初版把期望值写成 `floatStep` 本身（拿常量判常量），改常量的变异自然跟着改期望。
  这是 pin 自己的缺陷，已改成写死的绝对数，并在注释里记下这次差点放过。
- **M2** `FloatAlpha()` 直接返回 `TintAlpha`：`10%: the float (0.100) is not above the ground (0.100)`
  → 红（glassmap 与新 theme pin 双红）。
- **M3** `SolidTop 0.98 → 1.0`：`100%: the float (1.000) is not above the ground (1.000)` → 红。
- 三条都 `md5sum -c` 逐字节核对（`6ec69b75…`），并 `touch` 后复跑（无测试缓存复用）。
