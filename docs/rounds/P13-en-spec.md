# P13-en 规格：浮层的分组换行比它自己组内的两行还挤

## 意图（一句话）

**换一组要换得比换一行更明显**：浮层里「上一组最后一张卡 → 下一组标题」的空气是
**15px**，而同一组里「上一行 help → 下一行标签」是 **23px**——一个**组边界**比**组内的
两行**更紧，读起来不是「新的一组」，是「这一组多了一行小标题」。抬到一整档。

## 为什么现在做（证据）

`P13-em`「仍待」第 1 条把下一格指到「满态」（列表/卡填满视口时最后一行与容器下沿的空气）。
本轮先按纪律**先量**，三个表面各量一遍（`720×580` 设置页、`720×600` 浮层、`720×439` 启动器）：

| 表面 | 满态下沿的实测 | 判 |
|---|---|---|
| 设置页 | 最后一件文字盒底 **558.4**，视口 `H=580`，空气 **21.6px** = scroller 自己的 `Space(6)` | **对**（就是它的 padding，一个字节不多不少） |
| 浮层 | 最后一件文字盒底 **588**，band 底 **599**，空气 **11px**；scroller 底部 padding 是 `Space(3)` = **10.8px** | **对**（0.2px 取整） |
| 启动器 | 最后一行墨 **397**，列表视口底 **397**，空气 **0** | **对**（它是钉住的页脚，§6.1 表 1-10：页脚不参加折边，墨一直画到边上） |

**「满态下沿」三处是同一个答案，这一族没有病**。所以按纪律往下走一步——同一批帧里
顺手量的**另一格**倒了：

浮层停在开头（`PluginScroll.Y = 0`，`pluginSheetFrame` 浅色），沿 `x = band.Min.X+8 ..
band.Max.X-8` 逐行扫墨段（`spreadAt > 20`）：

```
ink seg  67.. 78 (h=12)   ← 浮层页头（插件名）
ink seg 100..109 (h=10)   ← 第一组标题
ink seg 129..501 (h=373)  ← 第一张卡（七个字段，连续）
ink seg 517..527 (h=11)   ← 第二组标题
ink seg 547..592 (h=46)   ← 第二张卡的开头
```

两个间隙：

| 对 | 实测（墨→墨） | 出处 |
|---|---|---|
| 第一张卡底 **501** → 第二组标题顶 **517** | **15px** | 外层 `Column` 的 `Gap(t.Space(3))`（`pluginsheet.go:74`），3u = 10.8px，加上标题行盒的上身 |
| 第二组标题底 **527** → 它自己第一张卡顶 **547** | **19px** | `sheetSection` 的 `Gap(t.Space(4))`（`pluginsheet.go:162`，P13-ej 刚抬过的那个数） |

**同一张浮层上，两个数说反了**：§4.3 立的规矩是「一个新的东西抬开一整档」，而
`Space(3)`（10.8）比 `Space(4)`（14.4）**低一档**——组与组之间比组内标题与卡之间还紧。
用户读到的是「第二组标题属于第一张卡」（它是第一张卡的最后一行小字），而不是
「这里换了一组」。§6.105 / §6.106 两轮都在抬**标题→卡**那一对（浮层 + 设置页各一半），
**没有一轮碰过「卡→下一组标题」那一对**——它就是这一族剩下的那一格。

## 逐条落地项

| # | 位置 | 现状 | 应改成 |
|---|---|---|---|
| 1 | `internal/settingsui/pluginsheet.go:74`，外层 `ui.Column` 的 `Gap` | `t.Space(3)` = 10.8px → 卡底→标题墨 **15px** | `t.Space(4)` = 14.4px → **19px**（与「标题→卡」同一档，一个字节不差） |
| 2 | `pluginsheet.go:162`，`sheetSection` 的 `Gap` | `Space(4)`，墨上 **19px** | **不动**（P13-ej 的结论） |
| 3 | 页头 → 第一组标题 | 页头墨底 78 → 标题墨顶 100 = **22px** | **不动**（同一个 `Gap`，一起被 #1 抬高 3.6px → 25.6px；页头是「这块面的名字」，与「换一组」不是同一对，但**同一条 column**，抬 gap 会连它一起动。判据：页头到第一组**本来就比组内宽**（22 对 19），抬完仍更宽（25.6 对 19），阶梯没被压平 → 接受） |

**为什么不给第二组标题补一条上内边距**（像 §6.106 对设置页做的那样）：那一列只有
「页头 / 失败线 / 各组」这些孩子，`Gap` 在这里**不是三对共用**——页头到第一组与
组到组是同一个角色（「一块新的东西开始」），抬它是对的。§6.36 的教训是「一个 gap
参数 = 第二个刻度回来了」，但那条教训的前提是**同一列里混着两种角色**；这一列没有。

**几何代价**：`MaxY` 330.8 → **334.4**（+3.6，一张分组卡之间一次）。两条旧 pin
（`sheetcutedge_test.go:218`、`sheetnamerung_test.go:106`）钉着 `330.8`，是 **V 类**，
按规矩重定基线并写 `P13-en 重定基线：旧值 330.8 → 新值 334.4`。

## 行为契约零改动红线

只改一个 `Gap` 的档位。不碰：高度链（`MaxY` 由内容自然长，不是常量）、键盘模型、
会话管理、设置写回、i18n 文案、命令接线。页头墨、分组标题墨、字段墨一律不动。
