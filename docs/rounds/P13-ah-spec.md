# P13-ah 规格：受光边讲「级数」，不是讲 alpha——浅色档的 E1 冠线一直没亮过

## 意图（一句话）

浅色档的 `LensRim`（0.09 白）压在近白面上只抬 **+3 级**（深色档同一条线抬 **+19 级**），
于是「这块面可以被碰」的记号在浅色档只是一个名义上的像素；本轮把浅色档的冠线订到
**同样的级数**（+19），深色档一个字节不动。

## 为什么现在做

任务书「先量再改的两个数」的第 2 条：`LensRim` 0.09 在浅色面上是否真看得见，组件级那条线要实测。
第 1 条（`Float` 档随 alpha 缩放）已由 P13-ac 量完并判为 `故意不做`；这一条还没人量。

## 量出来的数（`internal/settingsui` 真页面、真控件，`litProbe`，三通道和）

| 表面 | 档 | 冠线 | 面 | 冠线−面 | 对侧−面 |
|---|---|---|---|---|---|
| 会话页 28u 图标键（悬停） | 浅 | 224 | 221 | **+9（+3/通道）** | −39（−13/通道） |
| 同上 | 深 | 67 | 48 | **+56（+19/通道）** | −30 |
| 插件面板 28u 动作胶囊 | 浅 | 232 | 230 | **+6（+2/通道）** | −42 |
| 同上 | 深 | 58 | 39 | **+57（+19/通道）** | −24 |

结论：**浅色档的 E1 冠线是「+2~+3 级」= 1x 屏上画不出**（§1 判据「8 级下沿」）。
而且这不是「浅色天生只能这样」——浅色的头顶空间是 221→255 = 34 级，只用了 3 级；
E2 在浅色档用的本来就是近白 0.92（`EdgeHighlight`），说明这一支的语言里浅色的受光边
**就是**一条近白线。真正的差别是 E1 与 E2 的**比例**：深色 0.09/0.20 = 45%，
浅色 0.09/0.92 = **10%** —— 浅色档的「组件级」与「浮层级」不是同一族线的两档，是两种东西。

## 落地项

1. `internal/theme/theme.go` **浅色** palette：`lensRim 0.09 → 0.55`。
   - 依据：`221×(1−0.55)+255×0.55 = 239.7 → 240` = **+19 级**，与深色档的 +19 同值。
     **旧值 → 新值：浅色 `rgba(255,255,255,0.09)` → `rgba(255,255,255,0.55)`。**
   - 仍在 E2 之下（0.55 < 0.92，实测面 230 上 244 vs 浮层 254，差 10 级），仍在
     `TrackRim`（浅 0.70）之下，仍满足唯一材质不变量 `alpha(LensRim) > alpha(LensSheen)`。
   - `off` 档仍然 0（`litEdge` 的 `factor <= 0` 守卫在），普通/对比度阶梯关系不变。
2. `theme.Tokens.LitFace` 的注释：把「浅色 0.09 只抬 1~3 级，靠对侧」改成本轮的实测与
   新依据（对侧仍然必需，但它不再是**唯一**说得上话的那一半）。
3. `docs/liquid-glass.md`：§1 的 token 表与「新上限一句话」、§3 的「白压白」段、
   §6.0 差距表新增 0-11 行。
4. V pin：`internal/theme/theme_test.go` 的 `LensRim ≤ 0.09` 上限 → 按外观分档
   （深 0.09 / 浅 0.55），注释写 `P13-ah 重定基线：旧值 → 新值`。
   其余被撞红的浅色档 pin 逐条按 V 处置（旧值 → 新值 + 注释），B pin 零改动。

**不做**：不动深色档；不动 `LensSheen`/`LensEdge`/`TrackRim`/`EdgeHighlight`；
不动 `Lens()`（四层镜片的环会把冠线盖住，改它也不会改像素）。
