## 八项计划（先事件复现，不成立则不计成果）

1. shell.go:1842 / settingsui.go:2948：旧报告仍在、probes 已移除，仍可点刷新 → 当前声明不具备检查能力时撤下入口，保留历史报告。
2. 同入口：manifest 无法读取或身份不匹配，仍提供不可执行刷新 → 按当前有效声明撤下入口，恢复有效声明后重新可用。
3. shell.go:1924：健康刷新没有忙态 → 从开始到结束阻止重复启动，完成/失败恢复。
4. settingsui.go:4099/4108：健康刷新不参与行级锁 → 同行重连/检查/停用出口随既有忙态共同锁定，其他行继续可用。
5. shell.go:1926：运行时绑定失败仅写日志 → 使用已有失败通知，让当前操作明确结束，保留原报告和绑定故障详情。
6. 同处：仓库读取失败仅写日志 → 使用同一失败反馈，不能把失败当成功或留下永久忙态；恢复文件后可重试。
7. shell.go:1937：只刷新 Store，未更新 Launcher.SetCommands → 必选检查失败后撤下已不能运行的启动器命令。
8. 同处：检查恢复后命令目录仍旧 → 成功恢复后命令重新可达，尊重既有启用状态。
