# P13-ew · 滑块行的三对，以及它下面那行读数贴在卡沿上

## 意图

设置页的**滑块行**（`internal/settingsui/settingsui.go:4780` `a.slider`）是这一页上唯一
还在用「一条缝管所有对」的行：标题、提示、轨道、轨道两端的轴词、禁用原因，五个盒之间只有
一条 `Gap(t.Space(1))`。它上下的同类行（trailing 行、`stackedRow`）已经按对分缝
（§6.117，标题→提示读 6px）。同一页上同样两行字，这里读 13px。

紧挨着它的一组末尾还有一行读数（`a.effectiveOpacity`，`settingsui.go:4856`），它用另一条
竖缝：`Padding(t.Space(1), inset)` = 3.6，而卡片里每一行都是 8.1。于是这一组的答案被压在
卡片下沿的软边上——实测它的盒底离卡沿只有 **2.0px**。

## 先量的数（HEAD `4dd0e2c2`）

工具：`inkBands`（对比度 > 12 的连续墨带）。真页面 720×2600（General 页整页可见）、
合成卡 640×340（`sliderFrame`），深浅两套读数**逐字节相同**。

| 对 | 墨缝 |
|---|---|
| 标题 → 提示 | **13** |
| 提示 → 轨道 | **14** |
| 轨道 → 轴词 | **14** |

真页面 · 透明度组（两个滑块 + 读数行）：

| 对 | 墨缝 |
|---|---|
| 标题 → 轨道 | 11 |
| 轨道 → 轴词 | **14** |
| 轴词 → 发丝线 → 下一行标题 | 11 + 1 + 12 |
| 轴词 → 读数行（组末） | 18 |

合成卡 · 禁用滑块（`description` + `disabled` 同时在，五件齐全）：

| 对 | 墨缝 |
|---|---|
| 标题 → 提示 | 8 |
| 提示（末行）→ 轨道 | 12 |
| 轨道 → 轴词 | **13** |
| 轴词 → 原因句 | **10** |

两个结论，都在数上：

1. **轴词离自己的轨道（13/14）比离下面那句原因（10）还远**——「Transparent / Solid」不是
   轨道的一部分，读成下一段的开头。§4.3 的规矩是「间距属于它两侧那一对」：轨道与命名它两端
   的两个词是**一件东西**，这一对必须是全行最紧的一条缝。
2. **同一页上「标题 → 提示」读 13，而 trailing 行读 6**（§6.117 已定基线）——同样两行字，
   只因为控件在下面就读成两倍距离。

读数行（`effectiveOpacity`）：盒底 `1588.3 + 15 = 1603.3`，卡片下沿在 `1606` 附近，
合成卡上卡沿 `120` 对盒底 `117.99` —— **2.0px**。这一行是整张卡唯一不给自己留竖边的行。

## 落地项

1. `a.slider`（`settingsui.go:4780-4846`）：内列 `Gap(Space(1))` 拆成三对——
   - 标题 + 提示收进 `Gap(a.rowLineGap())` 的内列（与 trailing / stacked 行同一条缝）；
   - 轨道 + 轴词收进 `Gap(a.rowLineGap())` 的内列（一件东西）；
   - 外列 `Gap(t.Space(2))`：留给「那句话 → 轨道」与「轨道组 → 原因句」两对。
   墨 / 盒 / 控件 / 分隔线 / 读数 / 行计数一字节不动，只动缝。
2. `a.effectiveOpacity`（`settingsui.go:4856`）：`Padding(t.Space(1), inset)` →
   `Padding(t.Space(1), inset, t.Space(2.25), inset)`——上边仍紧（它是这一组的答案，不是
   又一行），下边补齐卡片自己的行边距，不再压在软边上。字阶、墨、盒宽不动。

**行为契约零改动红线**：高度链（每行只是 ±1.6px 的缝，没有新增/删除任何一件东西）、
键盘模型、会话管理、设置写回（`row.apply` 的触发条件与 `track.Changed()` 的读取位置不变）、
i18n 文案、命令接线，全部不动。视觉轮只改缝。
