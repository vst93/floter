## 这轮为什么让它更轻 / 更有空间感

层级（elevation）是**一套允许关系**：一环画在某个盒子上，就是在说「这枚能按、按了有反应」。
可禁用族量过四次，四次量的都是它看得见的那一半（指针 / 材质 / 一道淡 / 槽里的状态），
**没有任何一条问过键盘**。这一轮把「键盘不会停在一枚不肯接受它的控件上」读进帧里：
产品两臂在 Tab 之后是**零像素**静止，可用臂是 336 / 264 px。于是「轻」不是形容词——
一枚禁用的胶囊不是一枚「淡了的胶囊」，它是**一个没有键盘位置的盒子**，这两个说法现在由
同一张帧守着。反过来说，本轮量到的边界（半重的环留在已禁用的盒上）也说明这条关系
**现在只成立一半**：环还在，位置却已经不许按了。

## 一、先量（动手前，产品代码一个字节没动）

探针 = 三个 60×40 可聚焦盒（x=20 / 88 / 156，y=20），环带取盒外 `[X-3, X-1)` 两列、
上下各让 4 行避开圆角；地面 128（浅）/ 64（深）；和值 = R+G+B 的均值 × 3。

| 场景 | 浅色环带和 | 深色环带和 |
|---|---|---|
| 静止（无焦点） | 384 / 384 / 384 | 384 / 384 / 384 |
| Tab 1（焦点在盒1） | **270** / 384 / 384 | **506** / 384 / 384 |
| Tab 2（中间那枚禁用 → 焦点落到盒3） | 384 / 384 / **270** | 384 / 384 / **506** |
| Tab 3（绕回盒1） | **270** / 384 / 384 | **506** / 384 / 384 |

禁用盒的环带三次 Tab **一次都没离开 384**；落点顺序 盒1 → 盒3 → 盒1（禁用那枚被跨过，
键盘不在它身上费一步）。

产品真控件的对照（一页只放一枚，Tab 之后移动的像素数）：

| 臂 | 浅色 | 深色 |
|---|---|---|
| 胶囊可用 `actionButton` | **336 px** | 336 px |
| 胶囊禁用 `disabledActionButton` | **0 px** | 0 px |
| 槽可用 `switchControl` | **264 px** | 264 px |
| 槽禁用 `disabledSwitch` | **0 px** | 0 px |

**边界（本轮量到、写进需拍板）**：让键盘先落到中间那枚、再把它改成禁用。

| 帧 | 浅色 | 深色 |
|---|---|---|
| 焦点在中间（仍可用） | 384 / **270** / 384 | 384 / **506** / 384 |
| 中间当场变禁用（同一次重绘） | 384 / **327** / 384 | 384 / **445** / 384 |
| 再 Tab | **270** / 384 / 384 ← 倒退到盒1 | **506** / 384 / 384 |
| 再 Tab | 384 / 384 / **270** ← 才到盒3 | 384 / 384 / **506** |

① 环没消失，被框架的 `0.5` 淡成半重（浅 57 级 / 全重 114；深 61 / 122）——§6.2b-6 说
「禁用时灯要熄」，而**环是灯**；② 索引没重算，下一次 Tab 往回走，盒3 要多花一步。
两条都只能靠改键盘模型修（焦点重定向 / 遍历索引），是行为契约零改动红线 → 需用户拍板。

## 五、偷了什么（qiaomu-design · `craft-loop.md` 工艺密度菜单）

1. **第 4 项「签名交互：一个足矣」** → 落成「一页只放**一枚**控件，Tab 之后逐像素比对」。
   多放一枚就分不清「环落到了谁身上」与「环还在原地」。
2. **第 12 项「材质细节（盒与面分开量）」** → 落成环带只取 `[X-3, X-1)` 两列、上下各让 4 行：
   盒（60×40）与环（盒外 3u）是两个数，圆角的抗锯齿不许进读数。
3. **第 6 项「编辑细节：hairline / 编号表」** → 落成一张**臂 × 外观**表（胶囊 336/336、
   槽 264/264、禁用 0/0），每格一个实测数，不用「大约不动」这种话。
4. **第 2 项「空间节奏：一个盒子只占它需要的地」** → 落成「禁用盒的环带必须**恒等于**地面值
   384」——它不占那 3u。这条比「差得不明显」硬：差 1 级也红。
5. **A2 两轮制** → 「量」（两张表）与「立守卫」（两条 pin）在同一工作单元里完成；
   四视角评审见 §七。

## 六、preflight 逐条结论

- **第 0 步 · 偏好账本**：适用 P-1（禁斜体：本轮零字形改动）、P-5（可读性优先：判据本身就是
  「有没有东西被画出来」）、P-7（创意不吃功能契约：键盘可达性是功能契约，本轮只量不改）。
  P-2 / P-8（四方向预览 + 等点选）**不适用**：用户已钉死方向，任务书禁止本车道停下来等点选。
- **A 反 AI 套路**：通过。零新增视觉元素（无渐变 / 发光 / 斜体 / 三等分卡 / emoji），
  唯一新增物是**判据**与一张四张图的 dump。
- **B 设计读取一致性**：通过。三个读法与既有合约对齐：环在盒外（§6.146，P13-ga）、
  禁用的灯要熄（§6.2b-6）、槽里的状态还在（§6.150）。本轮没有引入第四种读法，而是补上
  第二道「环」的边界：**环不许落在不肯接受键盘的盒上**。
  **D2「正文 ≥ 14px」仍不过**——`tokens.Caption` 9.9px / 正文 10.8px 是沿用的未决项。
- **C 动效抽查**：通过。环没有过渡（框架即时绘制），`ReduceMotion: true` 全程开启；
  本轮零时长/缓动改动。**已知而非未测**：`busySwitchControl` 的 loader 相位与读数无关
  （本轮不量在飞那帧的轨道）。
- **D2 中文页**：本轮**不新增一个汉字**（i18n 红线）；dump 里没有文案，只有三个空盒子。
- **E 三秒测试**：通过。`stepped` 与 `stranded` 两张图并排，3 秒内能指出「环在哪一枚上」，
  而这两帧的产品差别只有一句 `.Disabled(true)`。

## 七、四视角偏执评审（各挑一处最弱）

- **艺术总监**：最弱的是 `stranded` 那半重的环——它在浅色上只有 57 级，看起来像「盒子自己的
  暗边」。**不加**装饰去区分：这一族只许有一道淡（§1），加第二层就回到 P13-s 判掉的老路。
- **工程师**：量尺最弱处是盒位置写成了常量。`lensProbe` 起点对齐 + 固定 60×40 + 8 gap
  使常量成立，但布局一改就静默错位——所以第二组 pin 用**整帧逐像素比对**（不依赖任何坐标）。
- **甲方**：三秒看完记住的是「禁用就是没有键盘位置」。功能契约成立。
- **读者**：禁用臂零像素这一点，是用户能感到但说不出的事——Tab 过去时它没有任何反应。
