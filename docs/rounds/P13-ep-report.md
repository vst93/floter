# P13-ep 报告：动作失败那句话是插件数据，而它与一枚 25.2px 的胶囊并排

表面：**插件配置浮层（plugin sheet）**。合约新增 `docs/liquid-glass.md` **§6.111**（状态：**需拍板**）。
规格 `docs/rounds/P13-ep-spec.md`。

**本轮没有产品改动**——这是「先量再改」给出的答案，理由在下面第三节，不许把它读成漏做。

## 一、意图与选题

`P13-eo`「仍待」第 1 条指向「浮层动作行的**在飞**状态」。**先量**的结果是：**没有在飞窗口**。

- `PluginSheet.Run` 的签名是 `func(key string)`，**不带回调**；
- `internal/launcher/config.go:149` `RunConfig` 是**同步**的：先清 `Armed`/`ActionFailed`，再当场调
  `a.Actions.ConfigAction(...)`，拒了就把 `ActionFailed` 写回去；
- 于是「按下确认」那一帧结束时结果已经在 state 里，下一帧画的就是最终态。
  **没有中间帧可画**，按纪律记 `故意不做`（理由：`Run` 同步；加 busy 臂要改签名 = 行为契约）。

于是按同一行量它的另一半：**失败那句话本身**（`pluginsheet.go` `sheetAction` 里
`ui.Text(c, field.Failed)`）。那句话是**插件写的**（`plugincfg.Field.Failed`），而它并排的胶囊
只有 25.2px 高，代码里没有任何宽度/行数约束。

## 二、先量（改前实测，深浅同值、两档宽度同值）

夹具：真 `PluginSheet`，1 组 7 个文本字段 + 1 个 `Action` 字段（`Failed` 由本轮控制），
装在启动器自己的链里（`Sunken` 面板 → 56px 字段行 + 4px 的带子）。窗口 720×300 与 420×240 各跑一遍。

| 读的是什么 | 无失败句 | 短句 `refused` | 长句（360 字符） |
|---|---|---|---|
| `PluginScroll.MaxY`（浮层内容高度） | 486.2 | 486.2 | **666.2（+180.0）** |
| `PluginScroll.MaxX` | 0 | 0 | 0 |
| 可见帧的墨范围（`convert -trim`） | — | `685×233+17+67` | `685×233+17+67`（**逐像素相同**） |

窄档同一组数：546.2 / 546.2 / **726.2（+180.0）**。

## 三、根因（把五个候选逐个实跑排掉）

| # | 注入（都是「那句话」上的排版约束） | `MaxY` 长句 | 结论 |
|---|---|---|---|
| M1 | `.SingleLine()` | 666.2 | 无效 |
| M2 | `.SingleLine().NoWrap()` | 666.2 | 无效 |
| M3 | `.SingleLine().Grow(1)` | 666.2 | 无效 |
| M4 | `.SingleLine().Shrink(1)` | 666.2 | 无效 |
| M5 | `.SingleLine().Ellipsis("…")` | 666.2 | 无效 |

五次注入全部实跑、全部读到同一个 `666.2`、五次都用 `git checkout internal/settingsui/pluginsheet.go`
逐字节还原（`git status --porcelain` 只剩本轮两个新文件）。

再加两条对照：

- 长句换成**一个 360 字符的词**（无空格，无从折行）→ 仍是 `666.2`：与「折了几行」无关；
- `MaxX` 始终为 0 → 不是横向溢出。

**结论**：180px ≈ 13 个 `Caption` 行盒，正好是行标签 `Clear history` 的**字符数**。
那句话的**最小宽度**（不可断的长词）把 `a.row` 的 `Grow(1)` 标签列压到了「一个字符一行」。
这是**行内 flex 的宽度争夺**，不是墨的问题——所以任何只作用在那句话上的约束都改不动它。
可见帧逐像素相同，是因为多出来的 180px 在折线以下：用户能把浮层多滚 180px，滚进去的是一列
被压成一字一行的行标签。

## 四、为什么本轮不改（需拍板）

能改的只有两处，两处都是**布局/几何**决定，按纪律不许擅自做：

1. **这句话该占多宽**——给一个宽度上限，等于替插件决定「失败说明能说多长」，会截掉信息；
2. **它该不该留在这一行里**——挪到动作行下面自成一行，行高就随失败而变（几何）。

两条都要用户点头，所以本轮交付的是**可复现的测量 + 合约条目 + 探针**，不是一次墨修补。
已写进 `.pending-bugs.md` 的「需拍板」。
