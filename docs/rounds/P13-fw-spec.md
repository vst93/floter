# P13-fw · 满态另一半：集成页命令列表 24 条，与「命令这一块不戴卡的缩进」

## 意图

会话页的满态在 P13-fv（§6.141）量过并修掉了「软边淡向窗口地」；同一族的另一半是**集成页
的命令列表**——它此前的 pin 全是三条命令（`commandlist_test.go`），"很多块板"这一态没有
量过。这一轮把满态量实，并修掉量出来的那个缺陷：**命令这一块（标题 / 说明 / 每一块板）是
集成卡的直接子节点，一个缩进都不戴**，板的 1px 边框紧贴在卡的 1px 边框上。

为什么现在做：P13-fv 报告「仍待」第 1 条给出的替代路径 = 满态的另一半，候选正是这一格。

## 证据（动手前实测）

帧 720×900，`internal/settingsui` 的 `renderIn`（装了 tokens 主题，与生产一致），
一条集成 × 24 条声明过的命令，深浅各一帧。`MaxY = 2730.30`。

- 板的节奏 **129.00**（23 个间隔逐值相同；板高 121 + 卡的 `Space(2)` 8），板与板之间
  **8 行卡的 `Control` 面**（浅 229 / 深 39）。
- **缺陷**：卡的左边框在 **x=187**（浅 216 / 深 51），命令板的左边框紧贴 **x=188**
  （浅 **194** / 深 **78**）——两块 1px 线中间**没有面**。右侧对称（板 702 / 卡 703）。
  同一张卡里的其他行（标题、权限、新鲜度）都在 **x=196**，`cardGeometry` 的注释也写着
  「命令列表共享这 8u 缩进」。
- 三条命令时这只是「板的边框盖住了卡的边框」；24 条命令时它是沿整张卡左右两侧从上贯到
  下的一条 **2px 双线**（216 + 194），读起来是一圈画框。
- 命令名 x=**200.80**（板边框 188 + 12 内距）；修后 208.80。
