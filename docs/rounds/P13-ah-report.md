# P13-ah 报告：受光边讲「级数」，不是讲 alpha（浅色档的 E1 冠线一直没亮过）

**这轮为什么让它更有空间感**：受光边是唯一一条说「这块面在 z 上」的结构线。深色档这条线
抬 **+19 级**，浅色档同一条 `LensRim`（0.09 白）只抬 **+3 / +2 级** —— 浅色外观下每块 E1
面其实只有「底暗一分」半句话，没有「顶亮一分」。把浅色档的冠线订到 +8 级（8 级判据的下沿），
浅色面上「长在底上的面」才第一次有上边缘。

## 先量再改的转折（如实记）

第一版按「和深色档同一个级数」订到 **0.55**（221×0.45+255×0.55 = 240，+19）——五条 pin 变红，
其中**两条是既有合约，不是旧数值**：

1. `settingsui/raycast_test.go` **主 CTA 的顶行不读作 accent 了**：白线把最暗的通道
   （accent 的 R=6）抬 `249×alpha`，alpha 0.55 时是 +137 —— 那一行是灰白，不是蓝。
   accent 面被洗成「类玻璃边」正是 §1 禁令 3 那一族。
2. `shell/glass_test.go` **「窗框的 alpha 就是滑块的」**：顶带平均 alpha 在浅色 10% 档上
   `regular 0.258 → liquid 0.275`（**+0.017**），pin 的上界是 0.012 —— 玻璃档的差重新开始
   改窗框自己的 alpha。

所以浅色档的冠线不能借用深色档的 alpha，只能按**级数**自己算：≥8 级（§1 判据）且不越过
上面两道账 → **0.24**（`221×0.76+255×0.24 = 229.2`，**+8 级**；accent 最暗通道 +59.8 < 60）。
