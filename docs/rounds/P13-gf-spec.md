## 意图

「禁用」这一族量过四次，四次都在这枚控件**看得见**的那一半：指针（§6.130，P13-fi 的 14 站点
普查）、材质（§6.2b-6，P13-s）、一道淡（P13-u）、槽里的状态（§6.150，P13-ge）。
**第五道腿——键盘——从来没人数过**。框架自己的承诺写在 `ui@v0.7.3/api_gen.go:3481-3482`：
disabled 的元素「report no clicks, **take no focus**」。这句承诺在本仓一次都没被读进过帧。

为什么现在做：产品里有真会走的路径。`rows.go:3817` 的修复键在**别的操作在飞**时变成
`Disabled(true)`、`settingsui.go:3243` 的「打开配置」在 provider 没声明 `openCommand` 时禁用、
`rows.go:1191` 的 kill 胶囊在确认态里禁用——用户在键盘上走到其中一枚，它**当场**失去可点性。
那一刻键盘去哪里，没有任何断言。

## 量（动手前，产品代码一个字节没动）

探针：`lensProbe`，三个 60×40 可聚焦盒（x=20 / 88 / 156，y=20），环带取盒外 `[X-3, X-1)`
两列、上下各让 4 行避开圆角。地面 128（浅）/ 64（深）。

| 场景 | 浅色环带和 | 深色环带和 |
|---|---|---|
| 静止（无焦点） | 384 / 384 / 384 | 384 / 384 / 384 |
| Tab 1（焦点在盒1） | **270** / 384 / 384 | **506** / 384 / 384 |
| Tab 2（中间那枚禁用 → 焦点到盒3） | 384 / 384 / **270** | 384 / 384 / **506** |
| Tab 3（绕回盒1） | **270** / 384 / 384 | **506** / 384 / 384 |

→ 禁用盒的环带在三次 Tab 里**一次都没离开 384**。可用臂与禁用臂的对照（产品真控件，
Tab 后移动的像素数）：

| 臂 | 浅色 | 深色 |
|---|---|---|
| 胶囊可用 `actionButton` | **336 px** | 336 px |
| 胶囊禁用 `disabledActionButton` | **0 px** | 0 px |
| 槽可用 `switchControl` | **264 px** | 264 px |
| 槽禁用 `disabledSwitch` | **0 px** | 0 px |

**边界（本轮量到、需拍板的那一格）**：让键盘先落在中间那枚上，再把那枚改成禁用：

| 帧 | 浅色 | 深色 |
|---|---|---|
| 焦点在中间（可用） | 384 / **270** / 384 | 384 / **506** / 384 |
| 中间当场变禁用（同一次重绘） | 384 / **327** / 384 | 384 / **445** / 384 |
| 再 Tab 一次 | **270** / 384 / 384 ← 倒退到盒1 | **506** / 384 / 384 |
| 再 Tab 一次 | 384 / 384 / **270** ← 才到盒3 | 384 / 384 / **506** |

两件事：① 环没有消失，只是被框架的 `0.5` 淡成了半重（浅 384−327 = **57** 级，全重是 114；
深 384−445 = −61，全重 −122）——§6.2b-6 说「禁用时灯要熄」，而**环是灯**；② 遍历索引没重算，
下一次 Tab **往回**走到盒1，盒3 要多花一步。两条都只能靠改键盘模型修，**本轮不动**。
