## 意图

键盘是**唯一在动的层**。一个 720×580 的设置页，正文高 1426、可见只 523：
用户按 Tab 往下走时，身体必须跟着走、且只往下走；走到底绕回时，身体必须回到顶上，
反向 Shift+Tab 是它的镜像。这条关系现在**没有任何一帧守着**——本轮把它量出来并钉住。

## 现状（实测，产品代码零改动前的值，720×580，light/dark 逐值相同）

正文 `a.Body`：`MaxY = 1426.0`；向下 16 步的 `Y` 序列

```
0 / 0 / 0 / 26.5 / 86.5 / 154.5 / 206.5 / 324.5
/ 457 / 572 / 664 / 749 / 872 / 1043 / 1125 / 1210
```

第 17 步**绕回**：`1210 → 184`（一次 −1026），随后 5 步停在 184（首屏那 5 枚），
再重新往下爬（206.5 / 324.5 / 457 / 572 / 664 / 749 / 872 / 1043…），
即**第二圈的顺序与第一圈一致**。每一步都有像素变化（最少 552 px），没有死站。

Shift+Tab 是镜像：13 步回到 184，第 14 步跳回 1210，随后 `1167 / 1059 / 950 / 827.5 /
709.5 / 641.5 / 589.5 / 529.5 / 410 / 286 / 184`，反向单调。

**顺带的防误判事实**：`Y` 落在 x.5 上（26.5 / 86.5 / …）**不会糊**。
同一份内容在 `Y=0` 的线行是 180/182（强度 30/6），在 `Y=26.5` 是 154/156（强度 30/6）
——整份内容按 **26** 行整行搬（取整由光栅器做），不是 26.5 行、
没有出现「两条半强度的行」。所以「把滚动偏移取整」不是本轮的活，也不需要。
