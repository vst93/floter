# P14 · 主题、尺寸与搜索交互修正

已完成用户提出的五项调整。保留此前的 mygo v0.8.3 升级及已有图片改动。

| Before | After | Why |
| --- | --- | --- |
| 切换主题时，部分控件仍显示上一主题的过渡色；独立输出/置顶窗口没有收到设置变更重绘通知 | 每个窗口在主题变化的首帧统一落到新颜色，并通知所有输出窗口重绘 | 消除混合深浅色与静态窗口长期保留旧颜色的问题，日常悬停反馈继续保留 |
| 标准比例 1.0，小号 0.9；设置窗口高度跟着控件缩放；动态搜索尺寸绕过工作区上限 | 标准比例改为 0.9，并成为默认选项；极小/小/大为 0.75/0.825/1.0。设置窗口独立使用 580 DIP，上限为工作区 80% 且留 24 DIP；搜索与配置页最高 720 DIP，并受当前工作区限制 | 采用用户认可的原小号比例，给设置保留阅读面积；系统尺寸约束和实际调整入口都执行上限，窗口长高时检查底边位置 |
| 设置文字按钮、图标按钮普遍以 36 DIP 为下限；搜索框图标仅约 14.4 DIP | 设置操作按钮按 28 DIP 下限和各自规格收紧；搜索框清除、会话、设置、插件配置和置顶图标提高到至少 18 DIP，点击区域至少 36 DIP | 区分表单操作与高频工具栏操作；开关/分段选择控件没有单独缩小 |
| 完整可见的搜索列表还能滚动约 3～4.5 DIP | 移除列表重复的底部留白，窗口几何计入上下边框并向上取整 | 四档尺寸下，最近启动/匹配结果/带反馈的 1、5、10 条列表共 36 个场景不再有额外滚动；受屏幕限制的长列表仍可滚动 |
| Super 增加额外提示带，并触发 150ms 窗口高度动画和列表滚动 | 有查询时选中现有底部操作；空查询时增加同样的终端操作行；路径优先选终端动作。按下、松开即时更新，底部操作不触发结果列表滚动 | 同一入口只出现一次；Super+Enter 执行选中的操作，空查询才打开空白会话 |

设置文件键和未知字段保留。终端本身仍按用户保存的尺寸调整；上述固定高度策略用于搜索、设置和插件配置面板。

## 验证

- 新增主题像素回归：同一实例在深浅色间切换，首帧逐像素对比新建实例；覆盖主窗口三种表面、系统自动主题、独立输出、置顶文本。主题选择器真实点击后无需再等待另一帧。
- Super 验证：空查询、已有匹配、无匹配的命令；单个底部入口、正确选择、执行路由、按下/松开高度、一次调整即到目标高度。原有编号、滚动、状态带及窗口尺寸合并测试同步更新并通过。
- 高度验证：未知工作区、200/600/900/2160 DIP 工作区，含负坐标显示器位置；设置高度不随控件比例缩放，受限长列表仍可滚动。
- 设置按钮的键盘焦点环和自定义快捷键草稿交互通过。两处旧夹具改为读取实际按钮边界或记录正确的草稿按钮位置，不再以旧高度或正在录制的邻居按钮位置推算。
- 生成 28 张常规深浅色/大小窗口预览与 8 张按实际内容高度绘制的 Super 状态图，检查了设置、集成与搜索入口；代表性截图保存在 [P14-ui-polish/](P14-ui-polish/)。
- gofmt、git diff --check、mygo vet、三平台 go vet/go build 通过。最后补齐独立窗口主题刷新后，又完成主题专项、macOS vet 与三平台构建。

全量测试 **未通过**：本次运行记录 2022 个顶层测试通过、107 个失败；其中 102 个与升级后基线重合。新增的 5 个是比例、Super 行数和控件位置的旧断言，均已更新并在专项测试中通过。详细名称、专项日志及压缩的全量原始日志见 [test-comparison.json](P14-ui-polish/test-comparison.json)。两个版本都在 launcher/settingsui 的既有像素采样测试中 panic，之后的用例没有执行，因此不宣称全量无回归；没有为此重复整套全量测试。

三平台构建和 vet 为本机交叉检查，界面验证使用生产 View 的无头渲染；未进行 Windows/Linux 实机、多显示器实机拖动或实际桌面读屏验收。未安装、发布或推送。
