# P13-en 报告：浮层的分组换行比它自己组内的两行还挤

表面：**插件配置浮层（plugin sheet）**。合约新增 `docs/liquid-glass.md` **§6.109**。
规格 `docs/rounds/P13-en-spec.md`。

## 意图

**换一组要换得比换一行更明显。** 浮层里「上一组最后一张卡 → 下一组标题」的空气是
**12.2px**，而同一组里「标题 → 它自己的卡」是 **14.8px**——一个**组边界**比**组内**
还紧，第二组标题读成第一张卡的最后一行小字。

## 先量（改前实测）

`P13-em`「仍待」第 1 条把下一格指到「满态」。本轮先按纪律把**满态下沿**在三个表面上
各量一遍（`720×580` 设置页 / `720×600` 浮层 / `720×439` 启动器）：

| 表面 | 满态下沿实测 | 判 |
|---|---|---|
| 设置页 | 最后一件文字盒底 **558.4**，`H=580`，空气 **21.6px** = scroller 自己的 `Space(6)` | 对 |
| 浮层 | 最后一件文字盒底 **588**，band 底 **599**，空气 **11px** ≈ 底部 `Space(3)` 的 10.8 | 对 |
| 启动器 | 最后一行墨 **397**，列表视口底 **397**，空气 **0** | 对（钉住的页脚不参加折边，§6.1 表 1-10） |

**「满态下沿」三处是同一个答案，这一族没有病。** 于是按纪律往下走一步，量同一批帧里
**另一格**，它倒了。

**量法**：盒对盒（同一种东西；墨对盒会把行盒上身算进空气）。卡的面从帧自己读——
`x = 300` 那一列在卡内、在字右边，只读得到卡的填充与它的一圈边；名字从 `Tester.Find`
读。`pluginSheetFrame`，深浅同值：

| 对 | 改前 | 改后 |
|---|---|---|
| 第一张卡底 → 第二组标题盒顶 | **12.2px** | **26.6px** |
| 第二组标题盒底 → 它自己那张卡顶 | 14.8px | **14.4px** |
| 浮层名字盒底 → 第一组标题盒顶 | 14.9px | **14.9px（一个字节不动）** |
| `PluginScroll.MaxY` | 330.8 | **345.2** |

## 落地

`internal/settingsui/pluginsheet.go`：分组循环把「这是不是第一组」传下去，

```go
for i, section := range plugincfg.Sections(sheet.Schema) {
    section := section
    a.sheetSection(c, sheet, section, i > 0)
}
```

`sheetSection` 拿到 `opensGroup` 之后，在**组自己**身上加一条上内边距：

```go
group := ui.Column(c).FillWidth().Gap(t.Space(4))
if opensGroup {
    group = group.Padding(t.Space(4), 0, 0, 0)
}
```

- 组内那一对（标题 → 卡）的 `Gap(Space(4))` **不动**（P13-ej 的结论）。
- 外层 `Column` 的 `Gap(Space(3))` **不动**——它同时是「页头 → 第一组」那一对。
- 只有从第二组起每组自带 4u = 14.4px 的一整档，`MaxY` 自然长 +14.4。

### 关键取舍：空气加在组身上，不是加在列的 `Gap` 上

第一版我把外层 `Gap` 从 `Space(3)` 抬到 `Space(6)`（一个更短的手），它**当场被
§6.105 的 pin 抓住**：

```
the first section heading's ink starts 55 rows below the band's top, want 44
(it was 44 before this round): the new gap belongs below the heading, not above it
```

原因：那一列的孩子是「页头 / 第一组 / 第二组」，`Gap` 是**三对共用**的一个数——抬它
把「页头 → 第一组」一起抬了（实测 14.9 → 25.7px），而那一对不是「换一组」。这正是
§6.106 已经立过的教训：**空气属于那一对，就加在那一对的元素上**。改法就是把空气从
`Gap` 挪到第二组自己的 `Padding` 上，页头那一对逐字节不动。

**为什么不是 `Space(5)`**（+2u，与 §6.105 / §6.106 同一步）：`Space(5)` 的盒间是 19.2px，
与组内的 14.4px 只拉开 4.8px，够不到「一整档」的下限 6px（§6.105 的 pin 用 6px 判）。
`Space(4)` 的上内边距拉开 **12.2px**，并把组边界落在 26.6px——§4.3 那条「一个可以按的
新东西」的 20px 档上，与 §6.69 会话页的 22px 同一读数。

## 用 qiaomu-design skill（「偷了什么」）

**读取为**：自绘桌面应用的配置浮层，面向正在改插件参数的用户，用「轻便液态玻璃」的
克制语言，倾向 `craft-loop.md` 的「工艺密度」而非新风格。拨盘：视觉冒险度 **4**（功能页，
不许新花样）、动效强度 **3**（这一轮不动效）、信息密度 **7**（配置表本来就密）。

**从 `craft-loop.md` 的工艺密度菜单取了第 6 项「编辑细节」与第 12 项「材质细节」，
但本轮只落前者，落成具体数值**：

- **第 6 项「编辑细节」**（章节间距的节奏）：菜单原话是「章节编号 / 页边注 / hairline /
  大写字距标签」。本仓的对应物是**分组标题的抬升量**。取的是它背后的规矩——「一组
  的开始必须比组内的换行更响」——落成 **14.4px 的上内边距（4u）**，让组边界从 12.2px
  到 26.6px，组内留在 14.4px。这与 §4.3 已经立过的三档阶梯（8 / 12 / 20px）对齐，
  不是新拍的数字。
- **第 12 项「材质细节」**（内边框高光 / glass 折射边）**判「故意不做」**：浮层里
  「面 + 受光边」的材质已经在 §6.19 / §6.72 收口，这一格是**间距**，再叠一层材质
  就是把两件事混在一轮里（任务书的「一轮只做一件事」）。

**两轮制**（`craft-loop.md` §三）：第一轮就是上面那个 `Space(6)` 的版本，**渲染**之后
被 §6.105 的 pin 判为「空气放错了地方」（见上「关键取舍」），第二轮只修这一处——
把空气从列的 `Gap` 挪到第二组自己的 `Padding`，再截图复核（bbox 从 y=517 起、
第一组零像素）。

### 四视角偏执评审（各挑一处最弱）

- **艺术总监**：这一格是**结构**不是**表情**——它让两组各自成立，但浮层整体仍然是一张
  长表，没有任何「这是哪个插件的什么能力」的层级暗示（分组标题与字段标签只差 2.6pt）。
  这一条**留给后面一轮**（属「层级」，不是这一格的间距）。
- **工程师**：`sheetSection` 多了一个布尔参数，调用点只有一处，但它的语义
  （`opensGroup`）与 §6.106 的 `sectionGroupPadded` 用的是**另一种**落法（那边加在
  标题行的下内边距上）。两处同族、两种写法——已在 §6.109 里写明理由（那边是三孩子
  一列、这边是组自己），但这是一笔**记账债**，下一个人要读两处才知道为什么。
- **甲方**：三秒看完能说出「这是两个配置分组」吗？——改前不能（两组连成一片），
  改后能（组边界 26.6px 与组内 14.4px 差 12.2px，眯眼也能分出两条带）。
- **读者**：`Second section` 与 `Toggle number 8` 之间现在隔 26.6px，比它到上一个字段
  的 help 行（14.4px）宽一倍——读的时候先看到「新的一组」，再看到「这一组的第一个字段」，
  顺序对了。

## preflight 结论（逐条，不能过的写为什么）

- **A 反 AI 套路**：过。无渐变、无发光、无 `#000000` 纯黑、无斜体、无三等分卡片、
  无「革命性/无缝/赋能」类文案（这一轮**一个字文案都没改**）。
- **B 设计读取一致性**：过。声明的拨盘（冒险度 4 / 动效 3 / 密度 7）与产出一致：
  只动了一个间距档，没有新色、没有新动效、没有新增控件。
- **C 动效抽查**：**不适用**（这一轮零动效改动；浮层的 160ms 入场在 §5 里，未触碰）。
  记在这里而不是静默跳过。
- **D2 中文页**：**仍未过**，且**不是本轮引入的**——`tokens.Caption` 9.9px / 正文
  10.8px 对 preflight D2 的「正文 ≥ 14px」。这是第 **63** 份证据，仍在
