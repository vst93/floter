# P13-eq 报告 · 过滤器 chips：一条做不到的缓动，与两条没人守的契约

表面 = **启动器的过滤器 chips 行**（`internal/launcher/filters.go`）。规格
`docs/rounds/P13-eq-spec.md`，合约新增 **§6.112**。

**这轮为什么让它更「轻」/更有空间感**：这一格是全仓唯一一处**声称**自己有 160ms 缓动、
实际却瞬变的墨——「轻」的前提是每一处过渡都真的在过渡；同时把它与结果行标题之间的
那条 34.2px 的列差**钉成有意的**，下一轮任何「对齐到 54u」的改动会立刻变红，而不是
悄悄把顶部 chrome 挪进列表的图标列。

## 量到的三件事

1. **一条做不到的缓动**。`filters.go` 的 chip 上挂着
   `Transition{Colors: true, Duration: theme.ColorStep}`。框架
   （`mygo@v0.7.3/ui/transition.go:17-19`、`:41-43`）只补间元素**自己的背景色与边框色**；
   这枚 chip 没有背景也没有边框，墨在子元素 `ui.Text` 上，**文字色不在补间列表里**。
   于是这条声明从来没产生过一帧动画——同族的 `fieldSettingsButton` 有面可补，才真的
   有那 160ms。声明一条框架做不到的缓动比不写更坏：下一个人会以为这里已经缓过了。
2. **点完还能打字，但没人守着**。探针实测：点 `Text` chip 后 `a.Query` 仍收字
   （`"" → "zz"`）。成立的原因是按键由外壳统一路由——`internal/launcher` 里 `Focus()`
   只有一个调用点（`FocusSearch`），**没有任何一处把焦点还给字段**。这条路径此前零测试。
3. **两条文字线，差一整个图标列**。chip x = **14.4**（`Space(4)`，字段那一列）对结果行
   标题 x = **48.6**（54u 文本列），差 **34.2**。这是**有意的**：chips 是这张卡顶部 chrome
   的一部分（与字段同一个内缩），不是列表里的一行。

## skill 用法（qiaomu-design · 打磨模式）

- **读取为**：桌面启动器的**模式过滤器行**，面向每天用键盘的重度用户，用**轻便液态玻璃**
  语言（受光边 + 面差 + 一个原点），倾向本仓自己的 `docs/liquid-glass.md` 契约。
- 拨盘：视觉冒险度 **3**（功能页、已有方向）/ 动效强度 **4**（这一格本来就该有 160ms）/
  信息密度 **6**。
- **偷了什么**（`craft-loop.md` 工艺密度菜单，逐条落到具体数值）：
  1. 第 **2** 项「过渡只给真正在变的属性」→ 落成：删掉 `Colors: true` 的空声明，
     并记录框架的补间白名单（背景色 / 边框色），所以这一格的悬停**不再假装**有缓动。
  2. 第 **5** 项「一条视觉线只能有一个原点」→ 落成：chip x `14.4` 与结果行标题 x `48.6`
     的 34.2px 差被写成判据（≥ 25 = 一整个图标列），而不是留给下一个人「顺手对齐」。
  3. 第 **9** 项「状态可点即须可验」→ 落成：`TestAChipClickKeepsTheFieldTyping`
     同时断言**选择生效**与**键盘仍在字段**。
- **preflight**：A（反 AI 套路）过——无玻璃叠玻璃、无渐变假高光、无装饰性光晕；
  B（设计读取一致性）过——这一格只动声明与判据，未引入第二种说法；
  C（动效抽查）**部分过**：本轮证明这一格**没有**动效且不伪造，文字色的补间框架不提供，
