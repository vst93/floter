### 第二批（3–4）

3. 现象：用户明确恢复默认成功后，旧拒绝提示继续占着页面。改动：显式恢复像开始录制一样开启本次尝试，先撤旧拒绝，再展示本次拒绝；已在默认值的 no-op 也可恢复。验证：深浅真实恢复按钮事件，成功后顶部与行内旧提示都消失。

## 偷了什么

- 从 `craft-loop.md` 工艺密度菜单 **#3 品牌 focus 环**取“让焦点准确属于可继续控件”：沿用 **2px** 环，错误出现/消失后的交接 **0ms**，稳定身份保证 Enter 仍指向原入口。
- 从 **#4 签名交互**取单一明确反馈：一次 Enter 对应 **1 次**恢复/录制尝试，第二次重试计数从 **1→2**，无自动追加写入。
- 从 **#6 编辑细节**取信息减法：保留 **1px** 发丝线，旧拒绝解决后占高 **0px**，没有新增常驻说明。
- 从 **#12 材质细节**取克制分层：沿用 E1 警告与控件的 **1px** 内受光边、**8px** 控件角，新增透明层 **0**。未为满足菜单五项硬加装饰。

Apple DESIGN 的 2px focus、8px 控件角及单蓝交互角色映射到已有 token，不复制网站字体/阴影，不引入 backdrop-filter。此轮使用已有方向路径，用户明确指令优先于四方案与网页 viewport 要求。
