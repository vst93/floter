# P13-k 报告：toast 顶部那条「渐变」量到底——它不是影，是背景透过玻璃

规格 `docs/rounds/P13-k-spec.md`。选题：`docs/liquid-glass.md` §6 在 P13-j 之后**没有
`未开始` 行**，按纪律走通用队列；队列第一条是 P13-j「仍待」第 2 条（一条已量到、未判定
的观察）。

## 1. 这轮为什么让它更轻 / 更有空间感

**因为本轮把「浮层的面被涂脏」这条指控撤掉了**：P13-j 记下的「pane 顶 14 行 241→202 的
纵向渐变」不是 E2 的影从面里透出来，而是**背景透过玻璃**——设置页内容区顶部那条 16px 的
`glass.ScrollEdge` 回放的是**不透明的**窗口底色，dump 台窗口后面没有桌面，于是那条带子在
合成后是 228 而框体是 137，toast 的 `Float` 面（可见合成 0.77）把它透出来就是 241→202。
真机上框体后面是桌面（浅色档框体本身就在 240 上下），同一条带子只有 4~6 级。

所以「轻」这一轴不用再往「给浮层加不透明度」这条错路上走——**面本身没问题，要动的是滚动
边缘的回放色**，而那一条需要拍板（§7）。这一轮的产物是把这条路封掉，并把尺子留下来。

## 2. 量到的三件事（全部实测，行号/数值都是本轮的）

### H1 · 不是它自己的影

隔离渲染（`internal/shell`，一个 `tokens.Float` 面 + `InputStroke` + `theme.ElevThrow` +
`EdgeHighlight`，480×200 台子），x=300 逐行 `R`：

- 浅色档 `plain`：盒内 **253 一整片**（40 行等值），盒外 255。
- 浅色档 `throw`：盒内仍是 **253 一整片**；影只出现在盒外的行上（`175 191 202 206 208 210 212 214 216 218`）。
- 深色档同一对读数：盒内 **24 一整片**（`throw` 也是 24），盒外 `17 18 19 19 20 20 20 20 20 21`。

mygo 的 `Shadow` 只画在 cast 矩形**外面**（`ui/paint.go:1216-1218` 的注释与
`scene.Op.Cast`），同一个元素上的影进不到自己的面里。**H1 否定。**

### H2 · 也不是兄弟的影

两张 toast 叠起来（缝 `t.Space(2)` = 8px），x=620 逐行：

- 缝里（上面那张盒底之下 1~6 行）：`100 105 107 106 103 109` —— 背景是 137，影在缝里
  **37 级**，这正是 §2 判据 3 要的「两层影同时在场」的缝。
- 下面那张的第一个内行：`194`，它自己的身体是 `202`，差 **8 级**；而同一行在**无 toast 的
  参照帧**上本来就是 220（同一条滚动边缘亮带），不是影。

**H2 否定**：上面那张的 throw 到下面那张的第一个内行已经衰减到读不出来。

### H3 · 是背景透过玻璃（成立）

无 toast 的参照帧，同一列 x=620：

```
y=40..63  116 116 …（框体）      y=64  110（内容区顶边）
y=65..79  228 221 215 208 201 194 188 181 174 167 161 154 147 140   ← 16px 滚动边缘
y=80..    137 137 137 …（内容区）
```

带 toast 时，pane 的内行 = `0.77×面 + 0.23×背景`：`143.6 + 0.43×220 = 238`（实测 238）、
`143.6 + 0.43×137 = 202`（实测 202）。**逐行对得上**，说明 pane 只是把背景按自己的 alpha
合成了一遍，没有任何东西画在它里面。

那条 16px 带子的来源是 `internal/settingsui/settingsui.go` 的 `body`：
`Material(glass.ScrollEdge{Background: t.Background})`，而 `t.Background` 是**不透明**的
`RGB(243,244,247)`（浅）/ `RGB(17,18,20)`（深）。插件把它按 `bg.Alpha(0.85)` 回放
（`plugins/glass/edge.go:91` 的 `softEdge = 0.85`），**替换** alpha 而不是相乘——所以
「回放框体那个半透明的面」在现有 API 上表达不出来。

## 3. 落地

   - `TestTheToastFaceOnlyAttenuatesItsBackdrop`（**常开 pin**，深/浅两条）：同一个 surface

## 7. 需拍板

**滚动边缘回放不透明底色**。窗口半透明时，`glass.ScrollEdge{Background: t.Background}` 回放
的是一个**屏幕上任何地方都不存在的颜色**：深色壁纸 + 浅色外观 + 低透明度时，设置页内容顶部
会出现一条 91 级的亮带（dump 台实测 228 对 137）。两条修法都要拍板：
①让插件支持「回放框体当前的合成色」（需要 mygo 侧 API，不只是本仓改动）；
②承认它只是滚动提示：把带子高度改成「条高 + 10 DIP」并只在真正滚动时出现，静息时不画。

## 8. 「偷了什么」（qiaomu-design / craft-loop 工艺密度菜单）

本轮走 `craft-loop.md` 的**打磨模式**（`SKILL.md` 的「已有方向，只要打磨」那条路径），
没有出四方向预览（方向已由用户钉死为轻便液态玻璃，自动车道没人能点选）。
读过的参考：`SKILL.md` → `references/user-preferences.md` → `references/craft-loop.md`。

| 取自 | 条目 | 落成的具体数值 |
|---|---|---|
| 工艺密度 **#5 多层染色阴影** | 「材质分两层说，只给浮层」——本轮把它量成了判据 | 缝里 37 级（`100` 对背景 `137`）是上面那张的 throw，下面那张的第一个内行只差 8 级且**与背景同相**：`|Δpane| ≤ |Δbackdrop| + 2` 就是这条菜单落成的数值 |
| 工艺密度 **#6 编辑细节：hairline** | 边界只留一条线，且不与受光边同色 | pane 的内行必须**等值跟随背景**（`143.6 + 0.43×B`），任何多出来的一条线/一层影都会让某一行偏离 → pin 逐行比 |
| 工艺密度 **#12 材质细节：内边框高光** | 受光边只画 1px，不许扩散 | 量到 `EdgeHighlight` 在 pane 上只占 y=59 一行（`250`），y=60 就回到面；pin 从 `label.Y-2` 起读，正好把这一行排除在外——**1px 就是 1px** |
| `user-preferences.md` **P-5 可读性优先于气质** | 用可读性否掉「加不透明度让它别透」 | 所以本轮**没有**动 `Float` 的 alpha：面本身没问题，动它等于用不透明换干净 |

## 10. 仍待

1. **§7 的滚动边缘回放**——需拍板（P13-k 新，取代 P13-j 的第 2 条）。
2. **§6.2b 9-11**（`control.SegmentedIndex` 选中段的 accent 环）仍是 `故意不做`，需拍板。
3. **`Float` 档的算术**（本轮量到、未改）：`FloatAlpha() = min(1, TintAlpha + 0.10)` 是**未补偿**
   的代数，`ContentAlpha()` 是**补偿**过的（`overFrame`）。于是 47% 框上浮层可见合成 0.772
   （比框的 0.47 高 0.30），而 100% 框上浮层与框**完全同值**（`min(1,1.1)` = 1）——不透明框
   下 E2 只有冠线和影、没有面。改它是一次全 E2 的视觉换血，需要单独一轮 + 拍板。
4. **P13-c 四条原样有效**：S1b（`CloseAll` 改 detach，等拍板）、S1c（Windows ConPTY）、
   客户端不告而别的检测、capture 通道迁移。
5. **P13-g / P13-h 的观察原样有效**：`t.Space()` 当 px 用的同源族未扫全仓；`iconPlate` 的
   暖面戴 `LitFace` 时深色档那条 0.09 白线读不出来（需拍板）。
