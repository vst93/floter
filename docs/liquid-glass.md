# 轻便液态玻璃合约（Liquid Glass, Light）

> **本文件是 `docs/raycast-design.md` 的升代。** 那一份钉的是「近黑底 + 1px 发丝线 +
> **无光泽** + 靠线分层」，是 P8 那一代的语言；它把光泽上限压到 `alpha ≤ 0.04`，
> 那条线是为「没有受光边」定的。用户 2026-10-30 换的总目标是**轻便液态玻璃**
> （半透明面 + 一层受光边 + 柔和外投影）+ **空间感**（明确的 elevation 阶梯，
> 靠面差 / 受光边 / 阴影分层，而不是靠画框）。
>
> 两件事直接冲突：**「无光泽」与「有受光边」不能同时成立**。所以这份文件显式地把
> 那条上限**重新定基线**（§1 末尾有 旧值→新值 表），并把 raycast 合约降级为
> 「行为契约 + 已落地条目」——它 §1~§5 的**语义 token 与行为契约全部继续有效**，
> 只有光泽上限与分层手段被本文件取代。
>
> 单一来源仍然是 `internal/theme/theme.go`：视图只读 `theme.Tokens`，不写字面色值。
>
> 切片：**P12-a = 合约 + 材质/层级 token 层升代（已做）**。表面切片逐轮推进，
> §6 的差距表就是选题队列；空表才算这一支做完。

## §0 本仓能画什么（自绘的物理边界）

本仓是 Go 自绘（mygo），**没有 `backdrop-filter`，也不许假装有**。等价物只有四件：

| 手段 | 本仓的实现 | 允许用在哪 |
|---|---|---|
| **面差** | 同一色相的三级 alpha（底 / 面 / 浮） | 全部三层，差值必须一眼看出（§1） |
| **受光边** | 1px 顶边更亮（`LensRim` 组件级、`EdgeHighlight` 浮层级） | 只给「面」与「浮」，底不画 |
| **阴影** | 环境影 + 接触影两层（`ShadowAmbient` / `ShadowContact`，`theme.ElevThrow`） | **只给浮层**，面板内元素不用 |
| **半透明** | 真透明度只给**窗口层**（`glassmap` 的 `main_opacity` / `glass_step` 链） | 只有窗口层；组件层不许自造透明 |

**硬禁令**（这一支的「反 AI 套路」）：

1. 不许拿模糊贴图 / 高斯近似 / 预渲染阴影图**冒充玻璃**。自绘没有 blur，就没有 blur。
2. **glass 不许叠 glass**：一个浮层内部不许再开一个浮层；浮层里的一切是「面」档。
3. **不许用渐变白边模拟高光**（用户原话里点名的「类玻璃边」）。受光边是一条 1px
   的实色线，不是 gradient。
4. 组件层不许自造半透明（否则叠起来必糊）；透明度只有窗口层那条链。

## §1 材质三档

一个应用里只有三种面。**同一色相**，只差 alpha；差值必须能在 1x 屏上一眼分开。

| 档 | token / 来源 | dark | light | 用在哪 |
|---|---|---|---|---|
| **底** ground | 窗框 tint（`glassmap.Spec.TintAlpha`，即 `main_opacity` 滑块）+ 卡的 sheen（`SheenTop`/`SheenBottom` ≤ 0.04） | 滑块（默认 47%） | 滑块 | 卡片/面板整体、设置页内容页（`Sunken` = 底 + 0.09） |
| **面** face | `Control` | `rgba(255,255,255,0.10)` | `rgba(0,0,0,0.07)` | 分组卡、字段、控件静息、行块底 |
| 面·指针抬起 | `ControlHover` | `rgba(255,255,255,0.14)` | `rgba(0,0,0,0.105)` | hover 抬一档 |
| 面·指针按下 | `ControlPress` | `rgba(255,255,255,0.05)` | `rgba(0,0,0,0.032)` | 按下沉到静息**之下** |
| **浮** float | `Float` = 窗框 tint + `glassmap.floatStep`（0.10），色 `#18191D` / `#FCFCFE` | 滑块+0.10 | 滑块+0.10 | 抽屉、弹层、toast、便条 |

**为什么「面」要抬到 0.10 / 0.07**：旧的 0.075 / 0.05 压在卡片自己的 sheen 上，
实测在默认 47% 的框上只差 3~4 个亮度级——用户读到的就是「所有东西挤在同一个 z 平面上」。
抬到 0.10 / 0.07 之后「面」与「底」的差在 1x 屏上是 8~11 级，一眼能分；而
`ControlHover` 与 `Control` 之间仍然只有一档（0.04 / 0.035），指针反馈不会变成跳变。

### 光泽上限的重定基线（旧值 → 新值）

旧的 `docs/raycast-design.md` §1 最后一行写着「低光泽上限（透镜/光泽/卡片 sheen）
`LensRim`/`LensSheen`/`LensEdge`/`SheenTop` 全部 ≤ 0.04」。**那条上限作废**，
换成「一条受光边 + 一片不反光的面」：

| token | 旧值（≤0.04 时代） | 新值 | 理由 |
|---|---|---|---|
| `LensRim`（组件顶受光边） | `0.04` | **`0.09`** | 这是**唯一**被允许亮起来的一条线：控件顶边 1px。旧值 0.04 在 1x 屏上画不出「受光」，只画得出一条噪点。**P13-ag 补一条**：`0.09` 是**在 `regular` 档**上的值，而受光边此前跟着 `--glass-lens-scale` 双向缩；对比度模式再乘 0.6，于是「要求更多对比」的用户在深色面上拿到 0.027 = **6 级**——又回到 0.04 那条线之下。现在对比度模式里 `LensRim` 有 0.75 的地板（`theme.LitEdgeFloor`）：深色 `regular` 冠线 +11 → **+13 级**，`frosted` +6 → **+12 级**；浅色 +1 → **+2 级**。普通档位**不动**（薄档仍然更安静：深色 `frosted` +18、`regular` +18… 见 §6.0 第 0-10 行）。 |
| `LensSheen`（组件宽面光泽） | `0.04` | **`0.04`（不动）** | 面**不许反光**。轻便玻璃的反光是「一条线」，不是「一片渐变」。 |
| `LensEdge`（组件底影） | `0.04` | **深 `0.20` / 浅 `0.06`** | 受光边要有对侧：顶亮一分，底暗一分，控件才站起来。**P13-n 重定基线**：深色的面是 39，0.06 只降 **2 级**（等于没画）→ 0.20 降 **8 级**；浅色的面是 230，0.06 已经降 **14 级**，而抬它会把 accent 面洗成类玻璃边（§1 禁令 3），所以浅色**不动**。旧值 → 新值：深 `0.06 → 0.20`，浅 `0.06` 不动。 |
| `TrackRim`（凹槽底受光边） | `0.09`（借 `LensRim`） | **浅 `0.70` / 深 `0.09`** | 凹槽的底边和面的顶边**不是同一条线**：浅色档的凹槽面上压着它自己的发丝线（`TrackEdge` 黑 0.08），0.09 的白叠上去只剩 **217 < 槽面 232**——受光边赢不了它下面那条环，凹槽读成「两条暗线的框」。**P13-o 重定基线**：浅色 `0.09 → 0.70`（实测底内线 221 → 242，−11 → **+10**，仍在地面 247 之下）；深色两者同值 0.09，**不动**（实测 +33，本来就亮）。 |
| `SheenTop` / `SheenBottom`（卡面） | `0.04` / `0.01` | **不动** | 窗口层的大面仍然是最轻的那一层；它靠透明度和外投影分层，不靠光泽。 |
| `SheenTopActive` / `SheenBottomActive` | `0.05` / `0.012` | **不动** | 聚焦档同上。 |

**新上限一句话**：`LensRim ≤ 0.09（深）/ 0.24（浅）`，`LensEdge ≤ 0.20（深）/ 0.06（浅）`，`TrackRim = 0.70（浅）/ 0.09（深）`，其余光泽 token `≤ 0.04`；且
`alpha(LensRim) > alpha(LensSheen)` 必须严格成立——**受光边比面亮**，这是这一支
唯一的材质不变量。`TrackRim` 是唯一的例外，理由只有一个：它画在**凹槽**上，不是画在面上；
浅色档的凹槽面本身已经是 232，一条 0.09 的白线在那里连自己下面那条环都盖不住。
pin 在 `internal/launcher/raycast_test.go`（`TestTheControlRimIsTheOneLitLine`）与
`internal/settingsui/groovepair_test.go`（凹槽的一对线，两套外观三个凹槽）。

### 禁用的材质：三种控件三种读法（P13-s / P13-t / P13-u）

「不可用」只有一个深度：**框架的 0.5 那一道**（`ui/paint.go:257-259`），产品**不许**再叠自己的
`Opacity`。材质按「这个控件有没有受光边可熄」分三种：

| 控件 | 材质 | 读法 |
|---|---|---|
| **面**（胶囊 / 按钮 / 卡片） | `theme.Tokens.DimFace` | 底对侧还在、**受光边熄了**——受光边是「这块面可以被碰」的记号（§3） |
| **槽**（字段 / 开关 / 列表框 / 凹槽） | 不叠材质 | 没有受光边可熄；靠「整块退一半、内线各留一半」表达「还在 z 上」 |
| **透明面**（只有墨的图标格） | 不叠材质 | 没有面也没有边；只剩一半的墨，不许长出面、不许戴受光边 |

禁用的**档位属于控件根**（`settingsui.lockedControl`）：一个 `Disabled(true)` 挂在根上，
整棵子树同乘 0.5；一个表单里出现 0.3 / 0.6 / 0.25 三种深度 = 同一句话说了三遍。

## §2 elevation 阶梯（三档，判据一句话）

空间感来自**层数少而差值明确**，不是来自更多层。

| 档 | 面 | 边 | 受光边 | 外投影 | 判据 |
|---|---|---|---|---|---|
| **E0 底** | 窗框 tint + sheen | 卡自己的 1px `InputStroke` | 无 | 窗口自己那一笔（Linux/Windows） | 它**是**窗口/面板本身 |
| **E1 面** | `Control` | 1px `ControlEdge` | `LensRim` 1px 顶边 | **无** | 它长在底上，压不出影子 |
| **E2 浮** | `Float` | 1px `InputStroke` | `EdgeHighlight` 顶边 | `ShadowAmbient` + `ShadowContact` 两层 | 它压在其他内容上，且可关闭 |

### §2.1 阶梯沿透明度滑块还站得住吗（P13-ac，**量过，不改**）

任务书「先量再改的两个数」第 1 条猜的是「透明度拉到 10% 时浮 0.20 对面 0.10 只差 0.10，
可能要按框的 alpha 缩放面档」。量下来**方向是反的**，而且真正塌的地方在**顶端**。
实测（`glassmap.SpecForPreferencesOS("linux", "regular", o, false)`，Linux 无平台 veil）：

| 滑块 | 底 `TintAlpha` | 浮 `FloatAlpha` | 浮−底 | 相对 |
|---|---|---|---|---|
| 10% | 0.10 | 0.20 | **0.10** | **2.00×** |
| 25% | 0.25 | 0.35 | 0.10 | 1.40× |
| 47%（默认） | 0.47 | 0.57 | 0.10 | 1.21× |
| 70% | 0.70 | 0.80 | 0.10 | 1.14× |
| 90% | 0.90 | 1.00 | 0.10 | 1.11× |
| 100% | 0.98 | 1.00 | **0.02** | 1.02× |

1. **面档不随框的 alpha 缩放**（判 `故意不做`）。alpha 差是**常数** 0.10（`floatStep`），
   所以相对抬升在低端最大；而浮层的颜色相对桌面是近黑/近白（`#18191D` / `#FCFCFE`），
   框越薄、透出的桌面越多，**像素**差越大。按 alpha 缩放会把两档拉平，正是反方向。
   `Control` / `ControlHover` / `ControlPress` / `LensRim` 是**画在 whatever 之上的洗色与线**，
   本来就不在滑块上。
2. **顶端那一档不靠 alpha 分家**（判 `故意不做`）。`SolidTop = 0.98` 封住底、`min(1, …)`
   封住浮，差只剩 0.02。浮层在那里由 §2 判据 3 的**两层影** + `EdgeHighlight` 顶边承担；
   把底从 0.98 压到 0.88 去换回 0.10 会改掉 `main_opacity` 的承诺（滑块就是框自己的 alpha），
   那是行为契约，不是墨。

pin：`internal/glassmap/floatladder_test.go`（六个档位，差值是写死的绝对数；
`floatStep` 本身也钉成 0.1）与 `internal/theme/theme_test.go` 的
`TestTheElevationRungsDoNotRideTheOpacitySlider`（10% / 47% / 100% 三档 × 深浅两套外观：
面档与受光边一个字节都不许动，浮仍严格高于面）。

**三条判据**：

1. **一个表面只有一个 E2**。抽屉开着的时候，抽屉里的一切是 E1；弹层开着的时候，
   弹层里的一切是 E1。同屏两个 E2 = 玻璃叠玻璃，禁止。
2. **E1 不许有外投影**。`Shadow(` 出现在面板内元素上就是越界（`internal/ci/elevation_contract_test.go`
   已经守着「投影必须走 `ElevThrow`/`ElevContact`」这条，本轮补的是「E1 根本不画影」）。
3. **E2 必须两层影**。只有环境影 = 浮层「贴」在底上；只有接触影 = 浮层「悬」在空里。
   两层同时在场才读得出「浮起来一张纸」。

## §3 受光边与阴影的数值

| token | dark | light | 用在哪 |
|---|---|---|---|
| `LensRim` | `rgba(255,255,255,0.09)` | `rgba(255,255,255,0.24)` | E1 的 1px 顶边（`theme.Tokens.Lens`）。**浅色档 P13-ah 重定基线：`0.09` → `0.24`**（见下），深色不动 |
| `LensRim`·对比度模式（P13-ag） | `0.09 × max(factor, 0.75)` | 同左 | 同一根线；`factor` 是档位系数 × 对比度 0.6。**旧行为 `0.09 × factor` → 新行为有地板**（见下） |
| `LensEdge`（对侧暗线） | `rgba(0,0,0,0.20)` | `rgba(0,0,0,0.06)` | E1 的 1px 底边（P13-n 重定基线，见下） |
| `TrackRim`（凹槽底受光边） | `rgba(255,255,255,0.09)` | `rgba(255,255,255,0.70)` | 凹槽（开关轨道 / 分段槽）的 1px **底边**（`theme.Tokens.LensInset`，P13-o 重定基线，见下） |
| `EdgeHighlight`（静息） | `rgba(255,255,255,0.20)` | `rgba(255,255,255,0.92)` | E2 的 1px 顶边、平台卡边 |
| `EdgeHighlightActive`（聚焦） | `0.24` | `0.96` | 同一根线亮一档（`cardedge.go`） |
| `ShadowAmbient`（环境影） | `rgba(0,0,0,0.62)` | `rgba(0,0,0,0.22)` | E2 宽投影 |
| `ShadowContact`（接触影） | `rgba(0,0,0,0.44)` | `rgba(0,0,0,0.12)` | E2 紧贴边 |

旧值 → 新值：`EdgeHighlight` 深 `0.15 → 0.20`（浅 `0.92` 不动，已经近白）；
`ShadowAmbient` 深 `0.55 → 0.62`、浅 `0.18 → 0.22`；
`ShadowContact` 深 `0.40 → 0.44`、浅 `0.10 → 0.12`。
两者**必须**保持 `Ambient > Contact`（宽的那笔更淡才散得开，而这里 ambient 的 alpha
更大是因为它铺得宽、像素上更稀——这是 base.css 的原始关系，不动）。

**受光边有地板，没有天花板（P13-ag）**：`LensRim` 跟着镜片档缩（0.5 / 1 / 1.6），这在
参考里是一格真阶梯——但**再叠一道对比度的 0.6** 就把它压到 1x 屏之下（0.027 = 深色面上 6 级），
而对比度模式的全部意义就是「把边给我看清楚」。所以对比度模式里 `alpha = 0.09 × max(factor, 0.75)`：
更厚的档位照旧更亮（`liquid` 0.96），更薄的档位被地板托住。**`off` 档（factor 0）不受地板影响**——
那档的整个意思就是「控件没有材质」，地板不许把它删掉的一条线复活（`theme_test.go` 的
`off kept a lens` 守着）。普通（非对比度）档位一个数都没改：深色 `frosted` 的 10 级是量出来的**安静**，
不是缺陷——实测（`internal/settingsui/rimstop_test.go`，真 `LitFace`）：

| 深色冠线抬升 | `frosted` | `regular` |
|---|---|---|
| 普通 | +10（不动） | +19（不动） |
| 对比度·旧 | +6 | +12 |
| 对比度·新 | **+12** | **+13** |

**浅色的受光边为什么是 0.92 而不是对称的 0.20**：浅色底上一条 0.20 的白线**看不见**
（白压白）。浅色的受光边只能是近白（0.92），它靠对侧的 `EdgeShadow` 才成立。
这不是两套规则，是同一条规则在两种底上的唯一解。

**组件级的浅色冠线（P13-ah）**：上面那句只对**浮层**（E2）是完整的说法。组件级（E1）
此前把 `0.09` 一个 alpha 套在两套外观上，实测差得很远（真设置页、真控件，三通道和，
1x 屏）：

| 表面 | 冠线−面（浅） | 冠线−面（深） |
|---|---|---|
| 会话页 28u 图标键 | 224−221 = **+9（+3/通道）** | 67−48 = **+56（+19/通道）** |
| 插件面板 28u 动作胶囊 | 232−230 = **+6（+2/通道）** | 58−39 = **+57（+19/通道）** |

即浅色档的 E1 冠线是 1x 屏上的**名义像素**（§1 判据：8 级下沿）。浅色的头顶空间是
221→255 = 34 级，此前只用了 3 级。**旧值 → 新值：浅色 `0.09` → `0.24`**（`221×0.76+255×0.24
= 229`，**+8 级**）；深色 `0.09` 不动（+19 已经够）。为什么不是「和深色一样 +19」：那需要
alpha 0.56，实测撞两道已有的账——① **accent 面的色相**：白线把主 CTA 顶行最暗的通道抬过
60/255，那一行就不读作 accent 了；② **窗框 alpha 就是滑块的**：顶带平均 alpha 偏 +0.017，
pin 的上界是 0.012。0.24 是这两道账之下、8 级判据之上的最大值——
**浅色档的冠线必须自己算级数，不能借用深色档的 alpha**。

**凹槽的底边是另一条线（P13-o）**：`LensInset` 的底边不是 `LensRim` 而是 `TrackRim`。
原因不是「凹槽更重要」，而是它下面**多压了一条线**：凹槽自己那条发丝（`TrackEdge`）
先把它压暗 19 级，受光边随后叠上去，0.09 只剩 +2 —— 净 **−15**。
实测（真设置页地面）：浅色槽面 232 ｜ 顶内线 184（−48）｜ 底内线 **221（−11）** → 改后 **242（+10）**；
深色槽面 36 ｜ 顶内线 29（−7）｜ 底内线 69（+33）**不动**。
两条规则合起来只有一句话：**受光边必须比它脚下的那一行更亮，且不许比它被切进去的那张纸更亮**
（浅色凹槽的底内线 242 < 地面 247）。

## §4 圆角与间距刻度（**不改**，只重申）

`docs/raycast-design.md` §2/§3 的度量全部继续有效，这一支**一个字都不改**：

| 项 | 值 |
|---|---|
| 圆角梯 | `RadiusXS` 6 / `RadiusSM` 8 / `RadiusMD` 10 / `RadiusLG` 12 / `WindowRadius` 12 / `KeycapRadius` 5 |

### §4.1 一行就是一行（P13-ae，**文字行为**，不是材质）

间距刻度的另一半是**文字占多少行**。一个行高 44u 的行是按「标题 18u + 灰线 15u」算出来的；
标题多折一行，这一行就不是 44u 了，卡的节奏正好在最长的那条名字上断掉。

规则只有两条，来源是参考 CSS 自己的分法（**不是**本仓的新发明）：

| 行的标题是 | 行为 | 参考出处 |
|---|---|---|
| **本仓写的句子**（i18n 文案、说明） | **可以折行**，`min-width: 0` 就够 | `.settings-row__label` / `__sublabel`，`settings.css:522-544` |
| **程序/别人给的值**（会话名、包名） | **一行 + 省略号**，`nowrap` + `text-overflow: ellipsis` | `.session-manager__row .settings-row__label`（`settings.css:1249-1260`）、`.extension-row__title strong`（`extensions.css:895-907`） |

**旧值 → 新值**：会话行与集成行的标题此前是**裸画**（无 `SingleLine`），折几行由容器宽决定——
460u 宽、长会话名下实测 **72u**（四行，把目录行从 `y=187.2` 推到 `y=241.2`），长包名下 **36u**
（并把版本 chip 挤到标题行下面）。现在两者都是 **18u** 一行。

落地与账：`settingsui/rows.go` 的 `rowName{Text, Nowrap}` / `rowValue()`；
`internal/settingsui/rowname_test.go` 三条（会话名一行、截断只截画笔不截数据 + 悬停读全名、
集成名一行且版本不掉行）。
**截断的出口**：`Tooltip(全名)`（参考没有，因为它的会话在别处
也能看到；本仓的设置页是读一个会话名的唯一位置）。

### §4.2 分隔符属于它引入的那条事实（P13-af，**文字行为**）

一行里的事实之间用 `·` 隔开时，这个 `·` **不是**行的一个独立子节点，而是**下一条事实自己的
第一个字形**（参考的 `::before`：`content: "·"; margin-right: 6px; opacity: .7`，
`extensions.css:979-984`）。理由只有一条：**折行是不可预测的**——dot 独立成节点，行一折它
就留在上一行的末尾，那一行以逗号收尾、下一行以光秃秃的事实开头，读起来是「句子被切错了
地方」。

| 位置 | 规则 | 墨 |
|---|---|---|
| 事实之间的 `·` | 折行时跟事实走（同一个文本节点） | `TextTertiary.Alpha(0.7)`（参考的 `.7`） |
| 状态字前的 `·` | 同上，但只给**透明**状态字 | 同上（状态字自己保持 `TextStrong` / `TextSecondary`） |
| 盒装胶囊（破损 / 推荐）前的 `·` | **不画**（参考的两个 `:not()`，`:986-995`） | — |
| 状态字与最后一个事实之间 | 8u 行 gap **+ 2u**（参考 `.extension-status{margin-left:2px}`） | — |

**旧值 → 新值**：dot 曾是行 `Row(...).Wrap()` 的独立 flex 子节点，460u 下三行**都以 `·`
结尾**；现在每行以 `· ` 开头（tester labels 从 `"·" "Managed"` 两个节点变成一个
`"· Managed"`）。状态字与最后一条事实的 gap 从 8.0u → **10.0u**。

pin：`internal/settingsui/metaline_test.go` 三条（dot 与事实同一节点且无裸 `·` 节点 /
透明状态字带 dot、胶囊不带 / 状态字落在 8u+2u）。



### §4.3 间距属于成对的两件东西，不属于区域（P13-aj，**已落地**）

空态区域（`settingsui/empty.go`）一直向 §4 的刻度问**一个数**——`Gap(8u)`——用在它里面
每两件东西之间。但间隙不是区域拥有的，是它**两侧那一对**拥有的：标记和它引入的那句话是
**一块**，句子和它的理由才是两块。而名义上的 8u 在墨上并不读成 8u——一枚 22u 的字形，
墨不填满它的盒子——所以 8u 的盒子间隙在墨上是 **12px**，与「句子→理由」的 **12px** 一模一样：
三件东西读成三个平级的邻居，标记悬在句子上方「自己一格」。

| 位置 | 旧 | 新 | 墨上实测（深浅同值） |
|---|---|---|---|
| 标记 → 句子（空态） | 区域统一的 8u | **4u**（标记与句子合成一块 `head`） | **12px → 8px** |
| 句子 → 理由 | 8u | 8u（不变） | 12px（不变） |
| 理由 → 动作（**板**：会话页的「新建会话」） | 8u + 2u margin（10u） | **8u + 12u margin（20u）**（P13-ap） | **14 → 23px**（深）/ **13 → 22px**（浅） |
| 理由 → 动作（**文字**：自定义快捷键的「添加第一条」） | 8u + 2u margin | 8u + 2u（不变） | 10px（不变） |

规则：**一个区域里只有「两件东西同属一句」的那一对可以内收**，内收量只取刻度的相邻一档
（8u → 4u）；**一个区域里只有「这一对里有一件是可以按的面」的那一对可以抬开**，抬开量取刻度
的一整档（+12u），让三对成阶梯 8px / 12px / 20px（同一块 / 同一段的下一行 / 一个新的东西）。
§4 的行高、水平度量、高度链一个字没动。墨一档没改（三档仍是
句子 `TextStrong` ≫ 标记 `TextSecondary` ≫ 理由 `TextTertiary`，实测 222 / 139 / 94 级）。

pin：`internal/settingsui/emptyink_test.go`——墨带检测（阈值 12 级 + 阈值 3 像素，降序合并
悬挂部）后三条账：①标记→句子比句子→理由**至少近 2px**（现在是 4px）；②标记下至少 6px 空气；
③三档墨序 句子 − 标记 ≥ 20 级、标记 − 理由 ≥ 20 级；深浅两套各一遍。
`internal/settingsui/emptyaction_test.go`（P13-ap）——④板的顶边离理由的墨 ≥20px 且 ≤34px、
板里的字仍在板内、⑤文字那一档仍 ≤16px（≈10px），两套外观。

### §6.4 扩展页（extensions / 设置页内的集成面）— **已落地（P13-e）**

**4-4 为什么给破损行写一条反面规则**：一个面的身份是**一条**受光边（§1 的不变量）；
破损行那条线已经被它的警告色内环占住（`Inset` 四边都在）。再叠一条白冠线会画进
同一个 1px 行，把「这块坏了」洗成「这块被选中了」。这不是少做一步，是「一个面只
说一句话」。

**4-3 复核的结论**：`extensionActionFace` 的 `tokens.Lens(button)` 第一层就是
`LensRim`（P12-a 已重定到 0.09），所以「受光边随升代自动到位」成立——本轮补的是
**证据**（像素 pin），不是代码。没改成 `LitFace`：胶囊的第四层 `ControlEdge` 环与它
自己的 `Border(1, ControlEdge)` 画在相邻的两行 1px 上，是同一条边的两次上色，不是
第二层画框；退掉它会让胶囊边缘从 2px 掉到 1px，那是几何改动，超出「只改墨与面」
的红线（观察记录在 `docs/rounds/P13-e-report.md`）。

### §6.16 满态的下沿不是一刀切：底边与顶边是同一道软边（P13-as，**已落地**）

§6.9 / §6.13 收的是**空态**的三件东西与它的出口；满态这一半到 P13-as 才补上。

- **判据（满态的下沿）**：滚动区两端的收口**必须成对**。一页比窗口长的内容，在窗口
  最后一行像素上不许有满对比的墨；最后一行相对于「软边上方那一带」的墨展开度
  （`max(luma) − min(luma)`）**≤ 45%**。实测改前 **110%**（222 / 202，浅色；深色同），
  改后 **19% / 20%**（39 / 202、40 / 198）。
- **判据（自门控）**：这道边不许在没有内容滚过时留下一道带子。滚到底（`Y = MaxY`）时，
  带内均值与上方两行相差 **≤ 6 级**（实测 0 / 1）。落地方式不是条件判断（那会在最后一帧
  留下陈旧状态），而是**几何**：底 padding `t.Space(6)` = 24px > 边高 `t.Space(4)` = 16px，
  滚到底时整条边落在空白上，渐变没有东西可淡。
- **判据（材料）**：底边的 `height`、`Background`、`PassThrough()` 与顶边**逐字段相同**
  (`settingsui.go` 的 `body`)；不许给底边换一种材质。
- **反直觉的一条**：这道边**不新增 padding**。顶边把 4u 预留成 padding 是为了让静止帧看不见；
  底边的 padding 早就在（6u，给页面末尾留白），再预留一次会把 `MaxY` 推大 4u、
  把每一页的内容位置整体上移——那是布局改动，不是墨。
- **两端的边穿哪张面（P13-au：量过，不改）**：两道边的 `Background` 都是 `t.Background`，
  而它们脚下是 `Sunken` 面板。此前这里记的是「浅色 229 / 深色 39 对 `Background` 247 / 14，
  理论上有一道 ~15 级的痕」——**那个前提是错的**：229 / 39 是 `Sunken` 压在**扩展卡**上的
  合成值，不是压在**窗口地**上的值。实测（720×580，General 页，上一轮 P13-at 的探针）：
  面板的合成面浅色 **246**、深色 **15**，窗口地 247 / 14——同一张面上只差 **1 级**，
  那道「痕」在 1x 屏上不存在，所以**不改**。

  才会把它推离地面（注入黑/白薄罩后浅色差 **42 级**、深色 **41 级**）。
