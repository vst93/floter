### Focus not restored to search input after closing terminal

When the user presses `Cmd+W` (macOS) / `Ctrl+W` (other platforms) on the
terminal view to dismiss it and return to the search/launcher page, keyboard
focus is not automatically placed back on the search input box. The user has to
click the input manually to start typing again, which breaks the flow.

**Expected:** Focus should return to the search input as soon as the terminal
view is dismissed, so the user can immediately continue searching.

## Optimization

### Rethink copy/paste shortcuts and terminal key passthrough

Currently, copy (`Cmd/Ctrl+C`) and paste (`Cmd/Ctrl+V`) are handled via
custom shortcuts that are intercepted by the app. This introduces two problems:

1. **Redundant and fragmented:** The custom handlers duplicate what the
   terminal already provides, but they only work in certain contexts — they
   feel inconsistent and "split" between the terminal view and other views.

2. **Blocks normal terminal input:** In a real terminal, `Ctrl+C` is
   SIGINT (interrupt process) and `Ctrl+V` is literal-insert / pasting raw
   bytes. Intercepting these shortcuts at the app level prevents the terminal
   from receiving them, so standard terminal keybindings can't be used as
   expected.

**Proposed direction:** Stop intercepting copy/paste shortcuts globally and let
the terminal handle them natively. Investigate whether the terminal view can
operate in a passthrough mode for these keys, so that:

- Inside the terminal: standard terminal keybindings (including `Ctrl+C` for
  SIGINT, `Ctrl+V` for literal insert) are forwarded to the PTY as-is.
- Outside the terminal (search bar, settings, etc.): normal OS-level
  copy/paste behavior applies.

This would make the terminal feel like a "real terminal" and eliminate the
custom shortcut layer.

### Light mode terminal color contrast

In light mode, several common CLI tools (e.g. `ls`, `git diff`, `eza`, etc.)
emit 8/16-color ANSI codes that were designed for dark backgrounds. On a light
background these colors — particularly light yellow, light green, and light
cyan — render with very low contrast and become nearly unreadable.

**Expected:** Terminal colors should have sufficient contrast in both light and
dark themes. Consider remapping the bright/light ANSI colors to darker variants
when the theme is light, or applying a contrast-aware color scheme so that
common tool output stays legible.
